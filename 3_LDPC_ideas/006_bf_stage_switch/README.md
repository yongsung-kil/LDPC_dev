# bf_stage_switch: 1bit 단계 전환 시점의 관측 기반 결정

출처: ieee:8742682 | 상태: 스크리닝 완료

## 📌 요약

- **논문이 제안하는 것**: BF(Bit Flipping, 비트 플리핑) 디코더를 여러 단계로 잇는
  다단 구조에서, 단계를 바꾸는 시점을 고정 반복 횟수 대신 디코딩이 루프(같은 추정
  벡터가 반복 재등장)에 빠진 때로 정하자는 제안. 추가로 1단계 파라미터를 "1단계
  단독 성공률 최대"가 아니라 "실패 프레임당 잔여 오류 수 ρ(로) 최소" 기준으로
  다시 고르라 한다
- **왜 효과가 있다고 보는지**: 루프에 빠진 뒤의 반복은 같은 상태를 맴돌 뿐이라
  낭비다. 루프 감지 시점이 프레임마다 다르므로 고정 횟수보다 전환이 정확하고,
  SNR(신호 대 잡음비)별 임계값 튜닝도 필요 없어진다
- **성공하면 무엇이 바뀌는지**: 현 C++ HD(Hard Decision, 경판정) 디코더의 고정
  4회 1bit 단계(HBF, Hybrid Bit Flipping) 전환이 프레임별 적응 전환이 되어,
  가망 없는 1bit 반복이 줄거나(조기 전환) 3bit 단계 진입 자체를 피한다(연장).
  에너지 대리 지표인 가중 반복 수가 줄고 FER(Frame Error Rate, 프레임 오류율)는
  유지된다
- **무엇으로 확인하는지**: 프레임마다 전환 시점을 0-8회 전수 탐색한 genie 상한
  (이득의 천장)을 먼저 재고, 상한이 의미 있으면 관측 가능한 감지기(syndrome
  weight 정체, 주기 2 진동, 플립 수 0)가 그 상한을 얼마나 달성하는지 본다

## 🔬 py 스크리닝 실험

### 환경

- 입력: H-matrix `matrix_sel_1.txt` (base 15x145, z=256, N=37120, K=33280),
  LLR matrix `LLR_MATRIX_HD_matrix_sel_1.txt` (HD, max_iter 120)
- 채널: fixed_error (프레임당 고정 에러 bit 주입), 에러 수 10-150bit 격자,
  포인트당 320프레임, seed 0
- 디코더: 이 폴더 decoder.py의 StageSwitchDecoder (BaseDecoder 상속,
  `decoder_main` 전체 재정의)
  - 1단계 = 1bit 포화 min-sum: `_vnu_quantize` 출력을 ±포화 크기로 고정.
    C++ VN_Cal_HD와 같이 dv > 5 열만 포화 (기본 포화 크기 7)
  - 전환 = C++ Clear_Edge_Restart 대응: CN 상태를 비우고 syndrome만 유지
  - 2단계 = 3bit min-sum (부모 동작, LLR 테이블을 1부터 다시 소비)
- 2단계 반복 예산 30회. 가중 반복 수 = 1bit 반복 × w1 + 3bit 반복 × w3
  (기본 w1=1, w3=3. 실패 프레임은 예산 전부 소모로 계상)

### 합성 방법 (scan.py)

현 C++ HD 구조는 전환 시 CN 상태를 비우고 syndrome만 유지하므로 2단계 결과가
1단계 진행과 무관하다. 그래서 같은 채널 프레임에 ㉮ 1단계 단독(8회, 궤적 수집)과
㉯ 3bit 단독(예산 30회)을 돌려 프레임별 (s1, s3)를 얻으면, 임의 전환 시점 t의
결과를 후처리로 정확히 합성할 수 있다. 구조적 따름정리로 프레임별 최적 전환은
t = s1(1단계 성공까지 유지) 또는 t = 0(건너뛰기) 둘 중 하나다 (중간 t는 1단계
진행이 버려지므로 결코 최적이 아니다). 합성의 정확성은 두 겹으로 검증했다:
㉠ switch_iter=0 모형과 BaseDecoder의 프레임별 일치, ㉡ 고정 4회 전환 실측과
합성 예측의 전 프레임 일치 (전 포인트에서 통과).

읽는 법 세 가지:

- ㉮ genie의 프레임별 선택은 전 포인트에서 유지(1단계 성공까지 계속)가 100%였고,

  1단계가 전 프레임 성공하기 때문이다. 그 결과 genie(0-8) = 고정 8회가 전 포인트에서
  일치한다. **genie 상한 전부가 적응이 아니라 "상한을 8로 늘린 고정 정책"으로 달성된다**
- ㉯ 조기 전환만의 상한인 genie(0-4)와 고정 4회의 차이는 최대 9.2%(E=150)로 연장
  방향(최대 25.7%)보다 작고, E 110 이하에서는 0이다
- ㉰ 1bit 단계는 이 영역에서 3bit 단독보다 2.0-3.0배 싸다 (HBF 구조 자체의 가치)

## ✅ 결론

**무의미** (논문의 두 제안 모두, 현 C++ HD 구조 기준).

- ㉮ 관측 기반 적응 전환: genie 전수 탐색이 조기 전환(건너뛰기 포함)을 한 프레임도
  선택하지 않았다. 8회 창의 1단계 실패는 루프가 아니라 느린 수렴이라 감지기가 잡을
  진동 신호가 없고, 실제 감지기는 침묵(주기 2 진동, 플립 수 0)하거나 오경보로 손해
  (syndrome weight 정체)였다. 논문의 루프 감지는 수십-수백 회 반복 후의 진동을
  전제하므로 4-8회 창의 우리 1bit 단계와 전제가 맞지 않는다
- ㉯ ρ 기준 재튜닝: 전환 시 CN 상태를 비우는 현 구조에서 1단계 잔여 오류는 2단계
  일량과 무관하고(합성 검증으로 확인), 측정에서도 ρ 최소와 비용 최소의 방향이
  일관되지 않았다
- ㉰ 파생 발견 (이 실험의 실질 수확):
  - ㉠ 구조 사실: 전환 시 1단계 진행이 버려지므로 프레임별 최적 전환은 "1단계 성공까지
    유지" 또는 "진입 안 함" 2택이다. 중간 시점 전환은 결코 최적이 아니다
  - ㉡ 고정 연장: 전환 상한을 4회에서 8회로 늘린 고정 정책이 genie 상한 전부를
    달성한다 (E 120-150에서 가중 반복 4.7-25.7% 절감, FER 손실 0, 이 측정 범위 기준).
    다만 이는 적응 기법이 아니라 ITER_MAX_HBF 상수 변경이며, 전처리 스케줄이 걸린
    하드웨어 변경(Decision 등급)이고, 1단계가 실패하기 시작하는 E 150 초과 영역에서
    연장이 손해로 돌아서는지 확인이 선행돼야 한다

한계: 전환 창 8회, 에러 수 150bit 이하, 포인트당 320프레임(FER 변별 없음), LLR
테이블이 3bit 단독용 튜닝이라는 간극 (decoder.py 모듈 docstring의 단순화 목록 참조).
