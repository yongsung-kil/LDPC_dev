보고서 작성 규칙

3_LDPC_ideas의 보고서(아이디어 README, 실험로그)에 적용하는 문장, 배치, 색 규칙이다. 사용자 첨삭에서 추출했으며, 첨삭이 쌓이면 이 문서에 규칙을 더한다. 절차와 양식은 새논문적용규칙.md 6절과 _template/README.md가 정본이고, 이 문서는 문장과 배치를 담당한다.

1. 문단은 문장 단위 bullet으로 나눈다

  • 여러 문장이 이어지는 긴 문단을 쓰지 않는다. 문장마다 bullet 하나를 준다
  • 항목 이름 bullet 아래에 내용 bullet을 한 단 더 들여 넣는다
  • 조건에 따라 갈리는 서술(격차가 크면 A, 작으면 B)은 조건을 상위 bullet, 귀결을 하위 bullet로 중첩해 쓴다
  • 들여쓰기는 한 단에 4칸이다 (render.py가 쓰는 markdown 패키지가 그래야 중첩으로 읽는다. 2칸이면 평평하게 펴진다)
  • 한 bullet은 짧고 쉬운 낱말로 쓴다. 내용을 줄이지 않고 bullet 수로 푼다 (긴 문장 하나보다 짧은 bullet 셋)

예:

- **논문 아이디어**:
    - 논문은 α를 고정하지 않고 min2 - min1 격차로 선택:
        - 격차가 크면:
            - min1이 확실히 가장 작음, 신뢰 높음
            - 높은 계수로 감쇠를 줄임
        - 격차가 작으면:
            - min1과 min2가 비슷, 신뢰 낮음
            - 낮은 계수로 감쇠를 키움

2. 문장 종결은 명사형

  • bullet과 표 칸의 문장은 "~함", "~됨", "~임"으로 끝낸다. "~한다", "~된다"를 쓰지 않는다
  • 예: "정규화 계수 하나를 고정하면 모든 검사식이 같은 감쇠를 받음"

3. 중요 단어는 bold

  • 각 bullet의 머리 단어(무엇에 관한 bullet인지)를 bold로 표시한다 (예: 디코더, 설정, 정규화 결과)
  • 문장 안에서도 정의되는 용어, 판정 기준, 핵심 수치는 bold로 표시한다 (예: 검사식에 들어온 메시지 크기의 최솟값(min1), T는 튜닝 필수)

4. 색은 두 가지, 개선은 빨강, 열화는 파랑

  • 아이디어에 유리한 결과(개선, 복구, 논문 주장 재현)는 빨강 bold로 표시한다: <span class="better">…</span>
  • 아이디어에 불리한 결과(악화, 손해, 논문 주장 미재현)는 파랑 bold로 표시한다: <span class="worse">…</span>
  • render.py가 두 class에 색을 입힌다. 문서마다 다른 색이나 class를 만들지 않는다
  • 쓰는 자리는 결과 표의 칸(수치나 비고), 지표별 해석, 요약의 실험 결과, 결론이다. 표 하나에 개선 몇 칸과 열화 몇 칸만 칠한다. 많이 칠하면 강조가 사라진다
  • 색만으로 뜻을 전하지 않는다. 칠한 글에 "개선", "악화", "복구", "손해" 같은 낱말이 함께 들어가야 흑백 인쇄에서도 읽힌다

예:

| (4,8,75,100,4) 클리핑+동적 | 0.00e+00 | <span class="better">5.21e-02</span> | <span class="better">전 조합 최량</span> |
| (15,15,85,100,4) | 1.00e+00 | 1.00e+00 | <span class="worse">감쇠 부족, 악화</span> |

5. 기호는 수식 표기로

  • 계수와 변수는 그리스 문자와 수식으로 쓴다 ("알파"는 α, 범위는 0 ≤ α ≤ 1)
  • 코드와 논문에서 영어로 쓰는 이름(min1, edge, α_high)은 억지로 번역하지 않고 영어로 쓴다

6. 항목 이름과 절 이름은 짧은 명사구로 고정한다

  • "성공하면 무엇이 바뀌는지" 같은 의문문형 항목 이름을 쓰지 않는다
  • 요약 절의 항목 이름은 다섯 가지로 고정한다. 순서도 같다:
항목 담는 것
논문 아이디어 논문이 무엇을 어떻게 바꾸자는지. 논문을 읽지 않은 사람 기준으로 쉬운 낱말
제안 이유 논문이 왜 효과가 있다고 보는지 (직관과 근거)
성공시 효과 성공하면 무엇이 얼마나 좋아지는지 (논문 보고 수치, 구현 비용)
개선 확인방법 어떤 지표로 효과와 그 이유를 확인하는지 (상세는 평가 계획 표)
실험 결과 판정, 핵심 수치, 조건과 한계 (8절)
  • 절 이름도 고정한다: 📌 요약, 📄 출처 상세, 📊 평가 계획, 🔬 py 스크리닝 실험, ✅ 결론, ⏭ 후속. "지표 계획"처럼 계획인지 지표인지 모호한 이름을 쓰지 않는다
  • 실험 절 안의 작은 절 이름도 내용이 바로 드러나게 짓는다 (바꾼 것, 실험 환경, 준비된 실험, 결과, 지표별 해석)

7. 나열 번호는 1. 2. 3.

  • 보고서의 나열은 markdown 순서 목록(1. 2. 3.)을 쓴다. 원문자 기호(㉮㉯㉰, ㉠㉡)를 쓰지 않는다

8. 요약 절은 실험 결과까지 담는다

  • 요약만 읽어도 무엇을 시험했고 어떻게 됐는지 알 수 있어야 한다. 아래 결과 절이 있어도 요약의 실험 결과 항목에 다시 적는다
  • 실험 결과 항목의 1단계 bullet 구성:
    1. 판정: {판정}. 뒤에 핵심 한 문장 (핵심 수치 하나와 성립 조건, 약어는 풀어서). 이 bullet이 대시보드 카드의 결과 줄이 된다 (16절)
    2. 핵심 수치 두셋 (개선은 빨강, 열화는 파랑, 4절)
    3. 조건과 한계 (어떤 전제에서만 성립하는지)
  • 머리줄의 상태도 같은 판정 낱말을 쓴다: 상태: 조건부 유효 (한 줄 사유)

9. 출처 상세는 bold 제목 bullet과 하위 bullet로

  • 항목 제목(논문, 핵심 아이디어, 논문 환경, 적용 분석 메모)을 bold로 쓰고, 내용은 한 단 아래 bullet에 둔다
  • 논문 bullet의 하위에는 제목을 따옴표로 묶고 괄호에 학회나 저널과 연도를 적은 줄, 아카이브 ID 줄을 둔다

예:

- **논문**:
    - "High-Throughput QC-LDPC Decoder with Cost-Effective Early Termination
      Scheme for Non-Volatile Memory Systems" (2014 학회)
    - 아카이브 ID ieee:6865738
- **핵심 아이디어**:
    - block-serial layered min-sum 복호와 겹쳐 돌며 패리티 검사식을 column
      단위로 누적 검사해 sub-iteration 경계에서 종료함
- **적용 분석 메모**:
    - [메모_ieee6865738_CBET.md](../_pm/tasks/...)

10. 이름과 내용이 짝을 이루는 나열은 표로

  • "항목: 설명" 꼴의 bullet이 세 개 이상 이어지면 표로 바꾼다 (예: 바꾼 것, 실험 환경 이름)
  • 열은 이름, 설정값, 설명처럼 성격별로 나눠, 설명 칸에 수치가 섞이지 않게 한다

11. 표의 제목과 설명은 표 앞에, 표 뒤에는 문장을 두지 않는다

  • 표마다 h4 제목을 붙인다 (예: #### 결과 1. LLR_MATRIX_HD_1 환경)
  • 표의 조건과 핵심 결과는 제목과 표 사이에 인용 블록(>)으로 두고, 안에서 항목마다 bullet을 준다 (조건, 핵심)
  • 표 뒤에 바로 문장을 두지 않는다. 표 뒤에 이어지는 해석은 다음 h4 제목 아래에 쓴다. 표 사이의 문장이 위 표 것인지 아래 표 것인지 헷갈리는 것을 막는다

예:

#### 결과 2. 상한 여유 환경

> - **조건**: 균일 ch=8, edge 레벨 {15,11,7,3}, 레벨 간격 4
> - **핵심**: <span class="better">클리핑+동적 결합이 전 조합 최량</span>

| 조합 | E=200 | ... |

12. 지표는 첫 등장에서 뜻과 판독 기준을 풀어쓴다

  • 지표 이름만 적지 않는다. 무엇의 비율인지, 값이 어디에 있어야 정상인지를 첫 등장에서 함께 쓴다
  • 예: "α_high 선택율 (전체 C2V 메시지 중 격차가 임계를 넘어 α_high가 적용된 비율. 0이나 1에 붙으면 고정 계수와 같아지므로 중간 값이어야 동적 선택이 작동하는 것)"

13. 함축 단어와 비유어 대신 사실 서술

  • "붕괴", "사망" 같은 함축 단어로 결과를 요약하지 않는다. 무엇이 어떻게 됐는지 수치로 쓴다 (예: "전 프레임 실패 (FER 1.0)")
  • 비유나 자체 조어로 측정 방식이나 상태를 부르지 않는다. 하는 일을 그대로 쓴다
쓰지 않는 말 대신 쓰는 말
그림자 측정 기록 전용 측정 (복호 판정은 그대로 두고 조건이 처음 성립한 자리만 기록하는 측정. FER 불변)
사망, 붕괴, 무너짐 전 프레임 실패 (FER 1.0), 반전 불능
건강한 기준선 정상 기준선 (FER 0)
견딤 한계 복호 가능 상한 (FER 0인 최대 에러 수)
사다리 n단 n단계 비교 구성
흑자, 적자 이득, 손해
되먹임 서로 영향
발화 정지 조건 성립
수확, 급소 발견, 핵심

14. 대조 조건은 구성을 자세히 서술

  • 실험 환경과 대조 조건은 이름과 수치만 적지 않는다. 무엇을 무엇과 비슷하게 만들었고 그래서 무엇을 가리는 조건인지까지 쓴다

15. 접속어 선택

  • 앞 내용에 덧붙일 때는 "추가로"를 쓴다. "여기에"를 쓰지 않는다

16. 대시보드 카드의 재료

  • python render.py가 아이디어 폴더마다 README.md를 읽어 대시보드(저장소 루트 index.html)의 카드 하나를 만든다. 카드를 누르면 md 옆의 그 README.html로 간다
  • 카드에 실리는 것과 README의 자리:
카드 자리 README의 자리 형식
번호와 제목 h1 # {번호3자리} {폴더이름}: {제목}
출처 머리줄 출처: {아카이브 ID} ({학회나 저널} {연도}) 뒤에 세로줄 기호와 상태: {판정} ({한 줄 사유}) (아래 예)
판정 점과 낱말 머리줄의 판정 낱말 (괄호 앞) 조건부 유효 / 실패 / 대기 / 실험중 / 반영됨 (점 색: 유효 초록, 실패 파랑, 실험중과 대기 주황)
아이디어 줄 요약의 논문 아이디어 첫 1단계 bullet 논문이 바꾸자는 것을 한 문장으로. 배경과 세부는 둘째 bullet부터 (카드에 싣지 않음)
결과 줄 요약의 실험 결과 첫 1단계 bullet **판정: {판정}**. 뒤의 한 문장 (핵심 수치 하나와 성립 조건, 개선 빨강과 열화 파랑). 카드에는 판정 머리를 뺀 나머지가 실림
논문 분석 메모 링크 출처 상세의 적용 분석 메모 하위 bullet의 첫 링크 없으면 카드에 링크 없음
  • 그래서 두 항목의 첫 bullet은 카드에서 혼자 읽혀도 뜻이 통하게 쓴다 (약어는 풀어 쓰고, 앞 bullet을 받는 "이것", "위"를 쓰지 않는다)
  • 요약 절 안에서 bullet 목록 뒤에 보통 문단(예: "참고) …")을 두면 거기서 항목이 끝난다. 카드에 실을 내용은 문단이 아니라 항목의 bullet에 둔다

머리줄 예:

출처: ieee:6865738 (2014 학회) | 상태: 실패 (기존 PCRC 대비 순증 절감이 전 구간 음수)
