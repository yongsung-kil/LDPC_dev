# 새 논문 적용 규칙 (정본)

새 논문 아이디어를 시뮬레이터에 붙이는 절차와 규칙의 정본이다.
README와 코드 docstring은 이 문서를 가리키기만 한다.

---

## 1. 구조 한눈에

```
2_LDPC_base/src/decoder.py 의 BaseDecoder   ← 유일한 디코더 클래스 (엔진 + C++ 대응 기준 구현)
        ▲ 상속 (run.py가 상위로 올라가며 2_LDPC_base를 찾아 import)
3_LDPC_ideas/{아이디어}/decoder.py                 ← 논문마다 새로 만들고, 바꾸는 교체용 함수만 재정의

3_LDPC_ideas/{아이디어}/run.py                     ← 실행 진입점. DECODER_CLASS 한 곳에서 디코더 선택
2_LDPC_base/workspace/base_run/                    ← 기준 실험: DECODER_CLASS=None(BaseDecoder), decoder.py 없음
```

- ㉮ **교체 단위 = C++ 함수 경계.** "교체 지점"이란 본체가 특정 단계를 일부러
  별도 함수로 분리해 둬서 아이디어 버전이 그 함수만 갈아끼울 수 있게 만든 자리다
- ㉯ 디코더 선택은 실험 폴더 run.py의 `DECODER_CLASS`가 한다 (config.json에는
  파라미터만 담는다)

## 2. 상속 경계: 어디까지 가져오고 어디부터 새로 만드나

- 1. **기본은 전부 상속.** 아무것도 재정의하지 않으면 base_run과 같은 동작이다.
     엔진(배치 처리, genie 판정, 로그, CN 상태 관리)은 실험 인프라라 새로 만들 이유가 없다
- 2. **논문이 바꾸는 단계가 교체용 함수 6개 중 하나면 그 함수만 재정의한다** (대부분의 논문)
- 3. **교체 지점에 안 맞는 근본적 변경**(직전 iteration 값이 필요한 damping, 진동 억제 등)은
     `decoder_main` 전체를 재정의한다. 이때도 `_init_state`, `_check_errors` 같은
     엔진 부품은 부모 것을 골라 호출해 재사용할 수 있다

## 3. 교체용 함수 표

| 논문이 바꾸는 것 | 재정의할 함수 | C++ 대응 |
|---|---|---|
| min-sum 변형 (offset/normalized/adjusted), C2V 보정 | `_c2v_reconstruct` | C2V_Cal |
| 양자화 규칙, 비균일 임계 | `_vnu_quantize` | VN_Cal_HD 양자화부 |
| 판정 규칙 | `_vn_decide` | VN_Cal_HD 판정부 |
| CN 상태 갱신 변형 | `_cnu_update` | CNU_Remove_Old_Sgn / CNU_Update_New_Mag |
| column 처리 순서 (layered / informed dynamic scheduling) | `_column_order` | 메인 루프 스케줄 |
| restart, perturbation, post-processing | `_is_edge_clear_iter` | Clear_Edge_Restart (Is_Iter_Type_Edge_Clear) |
| 테이블 row 선택 | `LLRMatrix.row_index()` (LLRMatrix 자식 클래스) | Get_Cur_LLR_Idx_FILE |

각 함수의 인자와 반환 형태는 `src/decoder.py`의 해당 함수 docstring
([교체 지점: C++ 함수명 대응] 표지)이 정본이다.

## 4. 절차 (예시: 동점 비반전 판정 변형, 이름 no_tie_flip)

### 1단계: _template 복사

`3_LDPC_ideas/_template/`를 `3_LDPC_ideas/{번호3자리}_no_tie_flip/`으로 복사한다
(run.py, config.json, README.md. 번호는 아이디어 현황표의 # 와 맞춘다).

### 2단계: decoder.py 작성

`BaseDecoder`를 상속하고 논문이 바꾸는 교체용 함수만 재정의한다.

```python
"""no_tie_flip: 동점 비반전 판정 (논문 출처, 연도).

재정의: _vn_decide (C++ 대응: VN_Cal_HD 판정부)
"""
from src.decoder import BaseDecoder


class NoTieFlipDecoder(BaseDecoder):
    def _vn_decide(self, sum_t):
        return sum_t < 0        # 본체는 sum_t <= 0 (동점도 반전)
```

### 3단계: run.py에서 디코더 지정

run.py의 `DECODER_CLASS = None`을 다음으로 바꾼다:

```python
from decoder import NoTieFlipDecoder
DECODER_CLASS = NoTieFlipDecoder
```

### 4단계: config.json 수정

필요한 파라미터만 바꾸고, `output.label`을 실험 이름으로 정한다
(실행 폴더 이름에 쓰인다). `output.dir`는 상대경로 그대로 두면 결과가
실험 폴더의 `Sim_Output/`에 쌓인다.

### 5단계: 실행과 on/off 비교

```bat
3_LDPC_ideas/no_tie_flip/ 에서 python run.py            :: on (아이디어)
2_LDPC_base/workspace/base_run/ 에서 python run.py      :: off (기준선)
```

두 config의 seed, 채널, 포인트, `run.frames_per_batch`를 같게 두면 같은 조건 비교가 된다.

### 6단계: README.md와 실험로그 기록

논문 출처, 요지, 재정의한 교체용 함수, 결과 요약을 README.md에 적는다
(양식과 작성 규칙은 6절). 실험 환경과 인사이트를 `3_LDPC_ideas/실험로그.md`에
기록하고, `python render.py`로 html을 갱신해 함께 커밋한다.

## 5. 중간 지표 규칙

최종 FER 한 줄만 보면 아이디어가 왜 들었는지, 왜 안 들었는지 설명할 수 없다.
실험 설계 시점(decoder.py 작성 전)에 README의 **평가 계획 표**를 먼저 채우고,
결과 절에서 지표별 해석을 적는다.

- ㉮ 평가 계획 표는 세 칸으로 적는다: 지표, 무엇을 판별하는지, 수집 방법
- ㉯ 최소 구성 두 가지:
  - ㉠ **논문이 효과의 근거로 제시한 중간 지표** 1개 이상 (수렴 곡선,
    iteration별 오류 수 등 논문 figure에 있는 것)
  - ㉡ **논문에 없어도 판정에 필요하다고 스스로 판단한 보조 지표** (아래 본체
    제공 지표에서 고르거나, 아이디어 특화 지표를 새로 정의)
- ㉰ 수집 방법은 세 갈래:
  - 1. 본체 로그: `decoder_main(log={...})`로 켠다 (아래 표)
  - 2. 아이디어 자체 수집: 재정의한 함수 안에서 직접 센다
       (예: 001의 클리핑 발생률, min1이 상한 P에 걸린 비율)
  - 3. 본체 확장: 다른 아이디어에도 쓸 범용 지표면 본체 `LOG_ITEMS`에
       추가한다 (Review 등급. 로그는 기본 꺼짐이라 속도 영향 없음)

본체 제공 지표 (`src/decoder.py`의 `LOG_ITEMS`):

| 켜는 방법 | 지표 | 무엇을 판별하나 |
|---|---|---|
| (항상 수집) | FER, BER, avg_iter | 최종 성능과 평균 수렴 속도 |
| log 아무 항목 | `log_active` (iteration별 미수렴 프레임 수) | 조기 종료 분포. iteration별 합계를 프레임 평균으로 바꿀 때의 분모 |
| `"csw"` | iteration별 패리티 검사 위반 수(CSW) 합 | 수렴 궤적. 줄다가 멈추는 정체, 오르내리는 진동 탐지 |
| `"bit_err"` | iteration별 비트 오류 합 (genie 기준) | 오류 감소가 멈추는 시점, 클리핑/양자화로 인한 교정 불능 탐지 |
| `"bit_err_by_dv"` | dv(변수 노드 차수)별 비트 오류 | 특정 dv 열만 오류가 동결되는 현상 탐지 (001에서 반전 불능 경계 확인에 사용) |
| `"fail_detail"` | 실패 프레임별 최종 CSW와 dv별 오류 | 실패 프레임 심층 분석 (오류가 몰린 dv, 남은 위반 검사 수) |

## 6. README 작성 규칙 (사람이 읽는 문서)

아이디어 README는 논문을 읽지 않은 사람이 처음 펼쳐도 이해되도록 쓴다.
양식은 `_template/README.md`가 정본이고, 문장과 배치와 색의 규칙은
[보고서작성규칙.md](%EB%B3%B4%EA%B3%A0%EC%84%9C%EC%9E%91%EC%84%B1%EA%B7%9C%EC%B9%99.md)가
정본이다 (항목 이름 고정, bullet 문장, 명사형 종결, 개선은 빨강, 열화는 파랑).

- ㉮ **요약 절이 맨 앞에 온다.** 다섯 항목을 이 이름과 순서로 쓴다 (보고서작성규칙 6절):
  - ㉠ **논문 아이디어** (논문이 무엇을 어떻게 바꾸자는지, 쉬운 낱말로, 한 문장씩 bullet)
  - ㉡ **제안 이유** (논문이 효과가 있다고 보는 직관과 근거)
  - ㉢ **성공시 효과** (논문 보고 수치, 구현 비용)
  - ㉣ **개선 확인방법** (어떤 지표로 효과의 이유까지 확인할지. 평가 계획 표와 연결)
  - ㉤ **실험 결과** (판정, 핵심 수치, 조건과 한계. 요약만 읽어도 결론을 알 수 있게)
- ㉯ **절 이름은 고정이다**: 📌 요약, 📄 출처 상세, 📊 평가 계획, 🔬 py 스크리닝 실험,
  ✅ 결론, ⏭ 후속. 이모지는 절 제목에만 하나씩 붙이고 본문에는 붙이지 않는다
- ㉰ **용어는 처음 나올 때 풀어 정의한다.** 업계 약어(CNU, dv, FER 등)는 첫
  등장에서 원어와 뜻을 함께 적는다
- ㉱ **실험 환경에 이름을 붙이면 정의부터 적는다.** 이름만 단독으로 쓰지
  않는다 (예: "원 토이 환경" 대신 "LLR_MATRIX_HD_1 환경 (dv별 ch 5/10/13/28,
  edge 상한 7)"처럼 실체를 함께 적는다). 측정 방식에 비유어를 붙이지 않는다
  (보고서작성규칙 13절)
- ㉲ **결과 표와 지표별 해석에는 개선과 열화를 색으로 표시한다.** 아이디어에
  유리한 결과는 `<span class="better">` (빨강 bold), 불리한 결과는
  `<span class="worse">` (파랑 bold). 몇 곳만 칠한다 (보고서작성규칙 4절)
- ㉳ **문서에 날짜를 적지 않는다.** 머리줄, 절 제목, 표의 어디에도 날짜를 두지
  않는다 (시점 기록은 git 이력과 `_pm/`이 담당하고, 실험 시점은
  `3_LDPC_ideas/실험로그.md`가 절 제목으로 담는다)
- ㉴ **md 수정 후 `python render.py`를 실행**해 형제 html과 대시보드
  `docs/index.html`을 갱신하고 함께 커밋한다 (md가 정본, html은 열람용). 대시보드
  카드는 README의 머리줄과 요약 절에서 만들어지므로 그 형식을 지킨다
  (보고서작성규칙 16절)

## 7. 지킬 규칙

- ㉮ `src/`(정본)에는 아이디어 코드를 넣지 않는다. 베이스 수리와 개선이
  모든 아이디어에 자동 전파되어야 하기 때문이다 (디코더 전체를 복사하는 방식을
  쓰지 않는 이유이기도 하다. 사본은 베이스 수리에서 누락되어 비교를 오염시킨다)
- ㉯ 재정의하는 함수의 **인자 목록은 부모와 같게** 유지한다 (엔진이 그 형태로 호출)
- ㉰ 생성자는 `(code, llr_matrix=...)` 형태를 유지한다 (run.py setup이 이렇게 호출)
- ㉱ `_cnu_update`를 재정의하면 받은 배열을 제자리에서 직접 고쳐야 한다
  (반환값은 쓰이지 않는다)
- ㉲ base_run 실험에는 디코더 코드를 두지 않는다 (`DECODER_CLASS = None`,
  재정의 0개가 기준선의 보증)
- ㉳ `_vnu_quantize`나 `_c2v_reconstruct` 재정의로 비정수 메시지가 생기면
  균일 등가식 전제가 깨진다 (`BaseDecoder._uniform_saturate` docstring 참조)
