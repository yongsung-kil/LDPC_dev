# 002 minsum_dynamic_normalization: min1/min2 격차 기반 동적 정규화

날짜: 2026-08-17 | 출처: ieee:6865103 | 상태: 조건부 유효 (실물 파라미터로 최종 판정 대기)

## 📌 요약

- **논문이 제안하는 것**: min-sum LDPC 디코더의 검사 노드(CNU, Check Node
  Unit)는 각 검사식에 들어온 메시지 크기의 최솟값(min1)과 둘째 최솟값(min2)을
  골라 정규화 계수(알파, 1 이하의 곱셈 계수)를 곱해 되돌려 준다. 논문은 이
  계수를 고정하지 않고 **min2 - min1 격차**로 매번 고르자고 제안한다: 격차가
  크면(min1이 확실히 가장 작음, 신뢰 높음) 높은 계수로 감쇠를 줄이고, 격차가
  작으면(min1과 min2가 비슷, 신뢰 낮음) 낮은 계수로 감쇠를 키운다. 여기에
  min1과 min2에 서로 다른 상한(P < Q)을 두는 이중 상한(001_minsum_dual_clip과
  같은 구조)을 결합한다
- **왜 효과가 있다고 보는지**: 정규화 계수 하나를 고정하면 모든 검사식이 같은
  감쇠를 받는다. 실제로는 min1이 min2와 확실히 구분되는 검사식의 메시지가 더
  믿을 만하므로, 신뢰에 비례해 감쇠를 조절하면 잘못된 확신의 전파는 억제하고
  올바른 정보의 전달력은 유지할 수 있다. 논문은 이 조합으로 비트 폭을 한 단계
  줄이면서(7비트를 6비트로) 성능 저하 없음을 보였다
- **성공하면 무엇이 바뀌는지**: 저비트폭 환경에서 무보정 대비 FER(Frame Error
  Rate, 프레임 오류율) 개선, 또는 같은 FER를 더 좁은 비트 폭으로 달성.
  구현 비용은 C++ 기준 C2V 재구성부에 비교 1회와 곱셈 1회 수준
- **무엇으로 확인하는지**: on/off FER 비교에 더해, 동적 선택이 실제로
  갈리는지(알파 high 선택율)와 고정 계수 대조군 대비 이득이 있는지를 본다
  (아래 지표 계획 표)

논문의 셋째 기법(저장하는 min2 값의 비균일 압축, Min2 Compressor/Expander)은
저장 비트 절감용 하드웨어 기법이고 논문 스스로 FER 중립을 목표로 설계했으므로
py 스크리닝 범위에서 제외한다. 실물 이식 단계에서 저장 비용이 문제가 되면
그때 참고한다 (후보 4번 ieee:11476755가 구현 참고용).

## 🔬 1단계: py 스크리닝 실험

### 바꾼 것

- 디코더: decoder.py의 MinSumDynamicNormalizationDecoder, 재정의 함수:
  `_c2v_reconstruct` (C++ 대응: C2V_Cal). 파라미터는 클래스 속성
  CLIP_P, CLIP_Q, ALPHA_LOW, ALPHA_HIGH, GAP_THRESHOLD로 전달
- 정규화 결과는 반올림해 정수로 유지한다 (비정수 C2V는 VNU 양자화의 균일
  등가식 전제를 깨기 때문. decoder.py docstring 참조)
- 설정: config.json은 base_run과 동일 조건 (seed 0, fixed_error [200, 300],
  frames_per_batch 64), label만 변경
- 조합 스캔은 scan.py로 실행. config 파일과 조합 목록을 인자로 받는다:
  `python scan.py [config파일] [P,Q,알파low%,알파high%,격차T ...]`

### 실험 환경 이름 (001과 동일)

- ㉮ **원본 LLR 환경**: 원본 C++에서 가져온 기본 조건. LLR 파일
  LLR_MATRIX_HD_1.txt (dv별 채널 LLR 크기 ch 5/10/13/28), edge 메시지 상한 7
- ㉯ **상한 여유 환경**: 균일 ch=8, edge 상한 15. 채널 정보 대비 edge 상한에
  여유가 있어 메시지 진폭이 크게 자랄 수 있는 조건 (config_headroom.json)
- ㉰ **비율 복원 환경**: 균일 ch=16, edge 상한 15. ch와 edge 상한의 비율을
  원본 LLR 환경과 비슷하게 되돌린 대조 조건 (config_balanced.json)

지표 계획 표의 중간 지표별 해석:

- **무효과 조합 일치**: (7,7,100,100)이 base_run과 E=200/300 모두 수치 완전
  일치. 구현 동등성 검증 통과
- **고정 대조군과의 분리**: 상한 여유 환경 E=300에서 고정 0.75는 1.00,
  동적(T=4)은 4.53e-01. 이득의 원천이 "정규화 자체"가 아니라 "격차 기반
  동적 선택"임이 분리 확인됨 (논문 Fig.5의 단계 개선 주장 방향 재현)
- **알파 high 선택율**: T가 인접 레벨 격차 이하이면 선택율이 0.99로 쏠려
  동적 구조가 무보정으로 퇴화한다. 원인은 본체(그리고 실물 하드웨어)의
  min2=RESET 승격 근사: min1이 교체될 때 min2를 실제 둘째 최솟값이 아니라
  최대값(RESET)으로 올려 두므로 격차가 과대평가된다. T를 "두 레벨 이상
  차이"로 잡아야(레벨 간격 4에서 T=4) 신호가 살아난다
- **선택율의 되먹임**: 같은 T=4에서도 알파 low가 0.85면 선택율 0.983, 0.75면
  0.321. 감쇠가 포화 분포 자체를 바꾸므로 선택율은 파라미터와 함께 움직인다.
  0.85는 포화 붕괴 루프를 끊지 못해 무보정과 같은 결과가 된다 (문턱 거동)
- **수렴 속도**: E=200 복구 조합의 avg_iter는 클리핑만 3.8, 클리핑+동적 4.3,
  동적만 6.4, 고정만 6.4. 클리핑이 수렴을 주도하고 동적 정규화는 E=300의
  실패 프레임을 추가로 살린다

## ✅ 결론

**조건부 유효**. 001과 같은 조건 구조(채널 LLR 스케일 대비 edge 상한의 여유가
있을 때만 이득)에, 이득 조건에서는 001을 넘어선다.

- ㉮ 이득 조건(상한 여유 환경)에서 클리핑+동적 정규화 결합이 E=300 FER
  5.21e-02로 전 조합 최량. 클리핑만(1.00), 고정 정규화만(1.00), 동적만
  (4.53e-01)을 전부 큰 폭으로 이긴다. 논문의 결합 주장이 방향 그대로 재현됨
- ㉯ 동적 선택의 격차 임계 T는 튜닝 필수: min2=RESET 승격 근사 때문에
  T < 레벨 간격이면 무보정으로, T가 너무 크면 고정 정규화로 퇴화한다.
  가이드: T = edge 레벨 간격 (두 레벨 이상 차이일 때만 알파 high)
- ㉰ 알파 가이드: low 0.75, high 1.0. low 0.85는 문턱을 못 넘고 0.5는 과함
- ㉱ 여유가 없는 환경(원본 LLR, 비율 복원)에서는 001과 마찬가지로 손해.
  실물 판정 사전 지표도 001과 공유: 실물 LLR set의 dv별 `ch / (edge상한 × dv)`
  비율이 1에 가까우면 여지 없음
