## 1. HIGH: C3의 min2 상한 모델이 본체 갱신 규칙과 어긋난다

**위치**: `분석메모.md:22` (C3), `th_as_clip.py:8-10`, `th_as_clip.py:63-64`
**본체 근거**: `2_LDPC_base/src/decoder.py:213-217` (`_cnu_update`)

본체는 새 메시지가 min1을 교체할 때 min2를 둘째 최솟값으로 내리지 않고 RESET(=7)으로 올린다.

```python
is_new_min1 = new_mag <= cur_min1
min2[:, row_blk, :] = np.where(
    is_new_min1, RESET, np.where(is_new_min2, new_mag, cur_min2))
```

th_as_clip.py는 이 규칙을 반영하지 않고 연결 column block의 실효 상한을 정렬해 `caps[1]`을
min2 상한으로 삼는다 (`th_as_clip.py:63-64`). 이 전제는 성립하지 않는다.

`check_agent1.py`에서 `_cnu_update`와 같은 규칙의 상태기계로 확인한 결과:

- ㉮ 연결된 모든 메시지가 5인데도 (min1, min2) = (5, **7**)로 끝난다 (초기 상태 (5,5,pos=-1), 메시지 [5,5,5,5])
- ㉯ 무작위 20만 시행에서 "min2 > 이번 iteration 메시지의 최댓값"인 사례가 다수 나온다

즉 **min2의 상한은 언제나 RESET = 7이고, th로는 낮출 수 없다**. 정확히는
`min2_final = 7`이 되는 조건이 "마지막으로 처리된 edge가 min1을 교체함"이라서, 상한이 낮은
dv가 섞여 있을수록 오히려 min1 교체가 잦아 min2 = 7이 자주 나온다.

따라서 C3의 결과값이 바뀐다.

| row | 메모 C3의 실효 (P,Q) | 본체 규칙 기준 실효 (P,Q) |
|-----|--------------------|------------------------|
| row 2 (iteration 2~4, CSW 984 초과) | (5,5) | (5,**7**) |
| row 57 (iteration 101~120, CSW 16 이하) | (5,5) 또는 (5,7) | (5,**7**) |
| 나머지 55 row | (7,7) | (7,7) |

**고치는 법**: C3을 "th는 min1 상한만 낮출 수 있고, min2 상한은 CNU가 min1 교체 시
min2를 RESET으로 올리므로 항상 7이다"로 다시 쓴다. 두 row의 실효 쌍은 (5,7)로 적는다.
`th_as_clip.py`의 `caps[1]` 자리는 `EDGE_MAX` 고정으로 바꾼다.

**연쇄 영향**:
- ㉮ C6 ㉯("min1 수신자와 min2 수신자의 비대칭 P < Q는 th로 만들 수 없다")는 예시 row가
  아니라 갱신 규칙 자체로 증명된다. 근거가 더 강해진다
- ㉯ C6 ㉮("7을 P로 자르는 비선형 상한은 ch와 th로 근사할 수 있다, row 2가 그 예")는 유지된다.
  row 2의 P = 5는 min1 상한 모델이 유효하므로 맞다
- ㉰ 이 규칙은 `3_LDPC_ideas/실험로그.md`의 002 인사이트 ㉮에 이미 기록되어 있다
  ("min1 교체 시 min2가 실제 둘째 최솟값이 아니라 RESET으로 올라가 격차가 과대평가"). 메모가
  프로젝트에 이미 있는 관측과 어긋난 상태다

## 2. MEDIUM: C3의 "실효 (P,Q)"가 iteration 안의 시점을 감춘다

**위치**: `분석메모.md:22` (C3)
**본체 근거**: `decoder.py:365-370`, `decoder.py:405-413` (column 직렬 제자리 갱신)

본체는 한 column을 처리할 때 그 column의 C2V를 먼저 전부 읽고 나서 CN 상태를 고친다.
따라서 한 iteration 안에서도 앞쪽 column이 읽는 C2V는 직전 iteration의 상태다.

`check_agent1_layout.py`로 확인한 column block 배치는 다음과 같다 (degree, 시작 index, 개수).

- dv11: 0~40 (41개), 129 (1개)
- dv4: 41~60 (20개)
- dv3: 61~128 (68개), 130 (1개)
- dv2: 131~144 (14개)

여기서 상한이 낮아지는 dv의 column 위치가 문제가 된다.

- ㉮ row 2에서 상한 5인 dv는 dv3이고 column block 61부터다. row 2가 처음 선택되는 iteration에서
  column 0~60(dv11 41개와 dv4 20개, 전부 정보 구간)은 상한 5의 영향을 전혀 받지 않는다
- ㉯ row 57에서 상한 5인 dv는 dv2이고 column block 131부터다. 그 iteration 안에서는 어떤
  column도 영향을 받지 않고, 다음 iteration부터 반영된다

**고치는 법**: C3에 "같은 row가 연속으로 선택되는 다음 iteration부터 반영된다"는 조건을 넣어
다시 쓴다. row 2는 CSW 984 초과가 iteration 2~4 중 2회 이상 이어질 때, row 57은 CSW 16 이하가
iteration 101~120 중 2회 이상 이어질 때 실제로 작동한다.

## 3. MEDIUM: A4 하위 임계값의 반대 방향 효과가 메모에 없다

**위치**: `분석메모.md:21` (C2), `분석메모.md:23` (C4)

C2는 "레벨 7 도달 불가" 칸만 세어 2개라고 적는다. `check_agent1_levels.py`로 네 레벨 전부에
대해 도달 가능성을 세면 그림이 달라진다 (228칸 = 57 row x 4 dv).

| 도달 불가 레벨 | 칸 수 | dv11 | dv4 | dv3 | dv2 |
|---------------|------|------|-----|-----|-----|
| 레벨 7 | 2 | 0 | 0 | 1 | 1 |
| 레벨 5 | 26 | 5 | 7 | 5 | 9 |
| 레벨 3 | 17 | 7 | 3 | 2 | 5 |
| 레벨 1 | 7 | 0 | 0 | 2 | 5 |

- ㉮ 실제로 쓰이는 레벨 수가 4개인 칸은 181개뿐이고, 3개인 칸이 42개, 2개인 칸이 5개다
- ㉯ 도달 불가 레벨이 하나라도 있는 row는 57 중 33개다
- ㉰ 예: row 57 dv3은 th = [7, 7, 1]이라 레벨 5가 통째로 비고 V2C가 {7, 3, 1}만 된다.
  row 57 dv2는 th = [9, 1, 0], ch = 0, |raw| 최댓값 7이라 레벨 7과 레벨 1이 모두 비고
  V2C가 {5, 3}만 된다

레벨 5가 비는 칸이 26개라는 것은 메시지가 3에서 7로 건너뛴다는 뜻이고, 이는 분포를 7 쪽으로
미는 작용이다. 클리핑과 정반대 방향이다.

또한 채널값만으로 최고 레벨에 닿는 칸이 적지 않다. th1 <= ch인 row 수는 dv11 20개, dv4 21개,
dv3 21개, dv2 21개이고 (57 row 중), 네 dv에서 동시에 성립하는 row가 6개다
(row 27, 28, 37, 38, 47, 48. CSW 임계값 768과 728).

**함의**: 레벨 분포가 7 쪽으로 밀리면 min1 = 7인 CN이 늘고, 그 상태가 바로 논문 (P < 7)
클리핑이 개입하는 자리다. C4는 "th의 압축이 약하다"는 사실만 적고 같은 사실이 클리핑 개입
여지를 넓힌다는 반대 방향 함의를 적지 않았다. C10 ㉯가 측정하려는 포화 CN 비율은 이 정적
분석만으로도 낮지 않을 것으로 보인다.

**고치는 법**: C2를 "도달 불가 칸"으로 일반화해 상단 2칸과 하단, 중간 47칸을 함께 적고,
C4 뒤에 "레벨 분포가 위로 밀려 포화 CN이 늘어나는 것은 클리핑 개입 여지를 넓히는 쪽이다"를
한 줄 넣어 C10 ㉯와 잇는다.

## 4. MEDIUM: B3 dv2 column block은 전부 패리티 구간이라 성공 판정에 직접 들어가지 않는다

**위치**: `분석메모.md:21` (C2의 row 57 dv2 칸), `분석메모.md:22` (C3의 row 57)
**본체 근거**: `decoder.py:324-327` (`_collect_error_metrics`)

- ㉮ N_b - M_b = 145 - 15 = 130이므로 성공 판정 대상은 column block 0~129다
- ㉯ 패리티 구간 130~144는 dv3 1개(block 130)와 dv2 14개(block 131~144)다
- ㉰ 즉 dv2 column block 14개는 전부 판정 범위 밖이다. 정보 구간의 degree 분포는
  {11: 42, 4: 20, 3: 68}이다

따라서 C2의 "row 57 dv2 레벨 7 도달 불가" 칸과 C3의 row 57 실효 상한은 성공 판정에 들어가는
bit와 직접 관계가 없다.

무관하지는 않다. `check_agent1.py`로 확인하면 **15개 CN row block 전부에서 마지막으로 처리되는
edge가 dv2 column의 edge**다 (마지막 column block 137~144). 위 1번에서 본 대로 min2 = RESET이
되는 조건이 "마지막 edge가 min1을 교체함"이므로, 판정에 안 들어가는 dv2 메시지가 각 CN의
iteration 종료 시점 min1, min2를 사실상 결정하고 그 상태가 다음 iteration에 정보 구간 column이
읽는 C2V가 된다.

**고치는 법**: C2와 C3의 dv2 관련 서술에 "dv2는 패리티 구간이라 성공 판정에 직접 들어가지
않고, CN 상태를 통해 간접으로만 영향을 준다"를 명시한다.

## 5. LOW: C1의 |raw| 최댓값 식이 성립 조건을 적지 않았다

**위치**: `분석메모.md:20` (C1), `th_as_clip.py:3`, `th_as_clip.py:41`

`max_raw = ch + (dv - 1) * 7`은 ch >= 0일 때만 |raw|의 최댓값이다. ch < 0이면 최댓값은
`|ch| + (dv - 1) * 7`이 되어 부호가 뒤집힌 쪽이 더 크다. `llr_matrix.py`의 모듈 docstring이
적어 둔 대로 restart row는 ch = -1을 쓰므로 이 갈래가 실재한다.

이 파일은 조건을 만족한다 (`check_agent1.py` 확인).

- ㉮ row_ch 범위 0~31 (음수 없음)
- ㉯ row_th 범위 0~31 (음수 없음)
- ㉰ restart_iters가 비어 있음 (restart row 자체가 없음)

**고치는 법**: C1에 "ch >= 0"을 조건으로 적고, `th_as_clip.py:41`의 `max_raw`를
`abs(ch) + (dv - 1) * EDGE_MAX`로 바꾸어 다른 LLR 파일에서도 맞게 한다.

## 6. 확인만 하고 문제 없는 항목

### A1 raw 정의와 캐스케이드 방향

- ㉮ 본체의 raw는 `vnu_out_raw = sum_t - vnu_in` (`decoder.py:407`)이고
  `sum_t = ch + Σ 모든 edge의 vnu_in` (`decoder.py:382-398`)이므로
  raw = ch + (다른 dv-1개 edge의 C2V 합)이다. C1과 일치한다
- ㉯ `_vnu_quantize` (`decoder.py:178-181`)는 아래 레벨부터 덮어써서 th1의 참 조건이 최종값이
  되고, `th_as_clip.py:41-44`의 정방향 첫 매칭과 같은 의미다. 비단조 th에서도 두 방식은 같다
- ㉰ 이 파일은 th 비단조 row가 없다 (`llr_matrix.py:222`의 `th_nonmonotonic`이 False,
  로더 경고 없음). `th1 < th2` 또는 `th2 < th3`인 칸이 0개다
- ㉱ 절댓값 비교 뒤 부호를 곱하고 (`decoder.py:182-187`) CNU는 `np.abs`로 크기만 받으므로
  (`decoder.py:411`) 부호 결합이 상한 계산에 끼어들지 않는다

### A2 min1 상한 모델과 min1_pos 초기값

- ㉮ min1이 이번 iteration 메시지의 최솟값을 넘는 사례는 무작위 20만 시행에서 0건이다
  (`check_agent1.py`). remove old가 min1을 올리는 갈래는 한 pass에 최대 한 번뿐이고 그때
  올라간 값도 이미 처리된 메시지들의 최솟값 이하라서, 결과적으로
  `min1 <= min(이번 iteration 메시지)`가 항상 성립한다. **C2와 C3의 P 부분은 유효하다**
- ㉯ `min1_pos` 초기값 -1 (`decoder.py:273`)은 어떤 edge 인덱스와도 같지 않아
  `_c2v_reconstruct` (`decoder.py:155`)가 iteration 1에서 모든 edge에 min1을 준다.
  iteration 1은 min1 = min2 = RESET이라 결과 차이가 없다
- ㉰ C10 ㉯의 전제("min1 = 7"과 "min1 = min2 = 7"이 같은 사건)는 성립한다. `_cnu_update`의
  세 갈래 어디서도 min2 < min1이 되지 않아 `min1 <= min2` 불변식이 유지되고, min2의 최댓값이
  RESET = 7이므로 min1 = 7이면 min2 = 7이다. 무작위 20만 시행 반례 0건. iteration 종료 시점만이
  아니라 iteration 중간 어느 시점에서도 성립하므로 C10 ㉯의 측정 시점을 따로 못박지 않아도 된다

### A3 상한 하락의 고정점

C2V의 절대 상한은 min1과 min2가 모두 RESET = 7 이하라는 점에서 나오므로, 어떤 dv의 실효
상한이 내려가도 다른 dv의 `max_raw` 안 (dv-1)x7 항은 내려가지 않는다. 그래서 1회 통과 계산이
곧 고정점이고, 반복 계산이 필요 없다. 이 근거가 메모에도 `th_as_clip.py` docstring에도 없으므로
한 줄 적어 두면 스크립트의 타당성이 자립한다.

### A5 균일 기준선 비교의 공정성

`th_softness.py:26`의 기준선은 `base_need7 = 7.0 - ch`로 파일의 ch를 그대로 쓴다. 따라서 ch
차이가 섞이지 않고 th1만 7로 바꾼 비교이며, C4의 서술은 맞다.

다만 기준선이 th1만 바꾸고 th2, th3은 바꾸지 않아 need5 쪽 기준선 비교가 없다. 참고로 파일의
th2 중앙값은 dv11 7, dv4 6, dv3 5, dv2 5로 균일 기준선 th2 = 5보다 높거나 같고, th1 중앙값은
dv11 13, dv4 9, dv3 8, dv2 7이다. dv11의 th1 중앙값이 기준선보다 6 높은 것은
"큰 차이가 없다"고 넘기기에는 dv11의 extrinsic 여지 70 대비 작지 않으므로, C4에서 dv11만
따로 언급하는 편이 정확하다.
