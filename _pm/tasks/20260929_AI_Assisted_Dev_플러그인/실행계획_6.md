# AI_Assisted_Dev 플러그인 실행 계획 (6단계: plan, review, debug, test-design 스킬 이관)

> 작성: 2026-09-30
> 설계: 3절 스킬 표의 "plan, review, debug, test" 줄, 4절 reviewer 에이전트, 판정요청 물음 6의 답(플러그인 자체 스킬로 넣음)
> 옮겨 올 원본: 홈 폴더 prompts의 plan.md와 plan_overlay_code.md, review.md, debug.md, test.md
> 판단: ㉮ 플러그인의 에이전트는 파일을 쓰지 못하므로 원본의 "결과를 파일에 기록"은 "본문으로 돌려주고 메인이 저장"으로 바꾼다. ㉯ 원본의 lv2(팀 리더가 워커를 부림)는 메인이 팀 리더 역할을 맡는 꼴로 바꾼다 (서브에이전트가 서브에이전트를 부르지 못한다). ㉰ 홈 폴더의 개인 경로 참조(오버레이 파일)는 스킬 본문에 녹인다. ㉱ 사용자 피드백 대기는 그대로 두되 "자동 진행 지시 시 멈추지 않음"을 덧붙인다. ㉲ test 스킬 이름은 `test-design`으로 (테스트 실행 명령과 헷갈리지 않게)

**목표:** `/ai-assisted-dev:plan`, `review`, `debug`, `test-design`이 원본 절차와 같은 라운드 구조로 돌고, 리뷰 작업자는 `reviewer` 에이전트(읽기 전용, git diff 허용)다.

## 파일

```
plugin/agents/reviewer.md
plugin/skills/plan/SKILL.md          (plan.md + 코드 오버레이 역할 표)
plugin/skills/review/SKILL.md        (딥과 라이트, 3라운드, 라이트 전환 기준, 최종 보고)
plugin/skills/debug/SKILL.md
plugin/skills/test-design/SKILL.md
```

## 작업

- 1. reviewer 에이전트와 plan, debug, test-design 스킬 작성
- 2. review 스킬 작성 (원본의 Round 3 검증과 최종 보고 절 포함)
- 3. validate, doc_check, 금지 표현 0, 커밋. 검사 사례 `review-light/`(작은 diff에 라이트 리뷰) 1건
- 4. `_pm/` 6단계 등록과 완료. 라이트 리뷰는 8단계까지 끝낸 뒤 한 번에 (2단계부터 8단계까지)
