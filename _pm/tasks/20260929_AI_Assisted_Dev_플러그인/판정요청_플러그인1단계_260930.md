## 물음 2. 자동 실행 스크립트를 부르는 명령에 운영체제별 실행기를 더할 것인가

- 🔎 예시: 플러그인에는 자동 실행 둘이 있다. 세션(Claude Code를 켜서 끌 때까지의 한 번의 대화)을 시작할 때 `_pm/TODO.md`에 확인 시각을 적는 것, md 파일을 고칠 때 문서 검사를 돌려 경고를 내는 것. 둘 다 `python` 명령으로 파이썬 스크립트를 부른다. 동료 A가 macOS에서 플러그인을 설치한다. macOS에는 `python3` 명령만 있고 `python` 명령은 없다
  - 1️⃣ 이면: 동료 A의 화면에 세션을 시작할 때마다, 그리고 md 파일을 고칠 때마다 "hook error"(자동 실행 오류) 한 줄이 뜬다. 스크립트를 못 찾아 오류 번호 127로 끝나기 때문이다. 동료 A가 README의 안내대로 `python` 명령이 `python3`를 가리키게 연결하면 사라진다
  - 2️⃣ 이면: 실행기 파일 하나를 더한다. Windows에서는 명령 프롬프트(cmd)가, macOS와 Linux에서는 셸(sh)이 같은 파일을 읽어 `python3`, `python` 순으로 찾아 돌린다. 둘 다 없으면 오류 표시 없이 그냥 끝난다. 동료 A는 아무것도 손대지 않는다. 대신 이 실행기가 Claude Code가 넘겨주는 입력 자료를 스크립트까지 제대로 전달하는지 세 운영체제에서 시험해야 한다
- 📌 상황: 지금 자동 실행 설정 파일(`hooks.json`)은 `python "…/pm_stamp.py"`처럼 `python` 명령으로 부른다. 이 PC(Windows)에서는 `python`이 있어 동작을 확인했다. 최종 검토자가 "고쳐야 함" 등급으로 지적했다. 동료들의 PC 운영체제를 제가 모른다. 전부 Windows면 1️⃣로 충분하고, macOS나 Linux가 하나라도 있으면 2️⃣가 맞다
- ⚠️ 문제: 실행기를 더하면 시험할 환경이 셋으로 늘고, 더하지 않으면 macOS나 Linux 사용자는 첫 설치에서 오류부터 본다
- ❓ 결정할 것
  - 1️⃣ (권고) 더하지 않는다. README 안내로 충분하다. 되돌리기 쉬움 (뒤에 더하면 된다)
  - 2️⃣ 더한다 (다음 단계의 첫 작업으로)
  - 권고 까닭: 지금 확인된 환경이 Windows뿐이고, 동료 PC가 Windows라는 전제라면 비용 없는 선택이다
  - 권고가 맞지 않는 경우: 동료 중 한 명이라도 macOS나 Linux를 쓸 때 (그때는 2️⃣)

  - 3️⃣ 그대로 둔다
  - 권고 까닭: 두 작업의 문서는 이미 사람이 읽을 꼴로 완성되어 있고, 올려야 다른 세션과 사내 PC가 본다
  - 권고가 맞지 않는 경우: 두 작업을 LDPC_dev에서 이어 가지 않기로 했을 때 (그때는 2️⃣)
