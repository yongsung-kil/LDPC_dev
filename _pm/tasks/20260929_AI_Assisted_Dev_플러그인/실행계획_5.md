# AI_Assisted_Dev 플러그인 실행 계획 (5단계: paper-search, paper-screen, paper-analyze)

> 작성: 2026-09-30
> 설계: [20260929_AI_Assisted_Dev_플러그인.md](20260929_AI_Assisted_Dev_%ED%94%8C%EB%9F%AC%EA%B7%B8%EC%9D%B8.md) 3절 스킬 표의 세 줄, 4절 paper-reader 에이전트, 7절 검색(브라우저 조종), 판정요청 물음 5의 답(사내 PC에서 브라우저 조종, IEEE 라이선스)
> 공통 제약은 1단계 계획과 같다. 옮겨 올 원본(논문 아카이브): 선별 기준서의 구조(대원칙, 포함 갈래, 제외, 판단 절차, 출력 형식), 선별 실행 안내서(청크 분할, 병렬 판정, 무결성 검증, 기록), 심층 분석 프롬프트(분류표, 알고리즘 요약 10줄, 모듈 대응, JSON), 분류 스키마(고정 선택지). 도메인 낱말은 옮기지 않고 프로파일에서 채운다
> 판단: 검색은 두 통로다. ㉮ 공개 API(arXiv)는 스크립트가 직접 부른다. ㉯ 라이선스가 필요한 곳(IEEE Xplore)과 특허(Google Patents)는 사내 PC에서 브라우저로 검색해 사이트의 "내보내기(CSV)"를 받고 스크립트가 들여온다. 브라우저 조종은 Claude Code의 브라우저 도구가 있으면 스킬이 직접 하고, 없으면 사용자가 내보내기 파일을 만든다. 전문(PDF)은 paper-reader 에이전트가 Read 도구로 직접 읽는다 (별도 추출 스크립트 없음)

**목표:** 프로젝트에 `papers/`(papers.db, criteria/, pdfs/, analysis/, catalogs/, _work/)가 생기고, 검색 결과가 db에 쌓이고, 초록 기준 병렬 선별(in/out)이 돌고, 통과 논문의 전문을 에이전트가 읽어 고정 선택지 분류표와 알고리즘 요약과 프로파일 모듈 대응을 md와 db에 남기며, 카탈로그 md가 만들어진다.

## 검토 초점

- 1. 같은 논문이 두 출처(arXiv와 IEEE)로 들어와도 DOI나 제목으로 한 번만 센다 (작업 1)
- 2. 내보내기 CSV의 열 이름이 대소문자나 공백이 달라도 제목, 초록, 연도, DOI를 찾는다 (작업 1)
- 3. 판정 결과에 db에 없는 id, 중복 id, in과 out 아닌 값이 있으면 기록하지 않고 알린다 (작업 2)
- 4. 분석 md의 JSON 블록이 깨져 있으면 그 논문만 건너뛰고 알린다 (작업 3)
- 5. 초록이 없는 논문은 선별 배치에 넣지 않고 따로 센다 (작업 2)

## 파일 구조

```
plugin/agents/paper-reader.md                논문 1편 읽기 작업자 (Read, Grep, Glob)
plugin/scripts/papers_db.py                  SQLite 접근 (papers, judgments, analysis 표), 중복 판정
plugin/scripts/paper_search.py               arxiv 검색, CSV 들여오기, 현황
plugin/scripts/paper_screen.py               batch, verify, apply, stats
plugin/scripts/paper_analyze.py              list(분석 대상), apply(분석 md의 JSON을 db로), catalog(카탈로그 md)
plugin/templates/papers/selection_criteria.md   선별 기준서 양식 (프로파일 낱말 자리표시)
plugin/templates/papers/categories.md           분류 스키마 양식 (공통, 하드웨어, 성능 갈래의 고정 선택지)
plugin/templates/papers/analysis_prompt.md      심층 분석 지시 양식
plugin/templates/papers/README.md               papers/ 폴더 설명
plugin/skills/{paper-search, paper-screen, paper-analyze}/SKILL.md
tests/test_papers_db.py, test_paper_search.py, test_paper_screen.py, test_paper_analyze.py
```

## 작업 1: `papers_db.py`와 `paper_search.py`

**db 표:** `papers(id TEXT PK, source, title, abstract, year INT, venue, doi, url, pdf_url, status, added_at)`. status: new | in | out | analyzed. id는 `arxiv:{번호}`, `doi:{doi}`(DOI가 있으면), 없으면 `{source}:{제목 해시 앞 12자}`. `judgments(id, decision, reason, run_dir, at)`, `analysis(id, json TEXT, md_path, at)`.

**인터페이스:** `papers_db.connect(path)`(표 생성), `insert_paper(conn, row) -> bool`(중복이면 False. DOI 같으면 중복, 없으면 제목을 소문자와 공백 정리해 같으면 중복), `stats(conn) -> dict`, `pending_for_screen(conn, limit, year=None) -> list`(초록 있는 new만), `count_without_abstract(conn)`.

`paper_search.py`: `arxiv_query(query, max_results, since_year) -> list[row]`(urllib로 export.arxiv.org API, Atom을 xml.etree로), `parse_arxiv_atom(text) -> list[row]`(테스트는 이 함수로), `import_csv(path, source) -> list[row]`(열 이름을 소문자와 공백 제거로 정규화해 title, abstract, year, doi, url, pdf 찾기. IEEE 내보내기의 "Document Title", "Abstract", "Publication Year", "DOI", "PDF Link"와 Google Patents 내보내기의 "title", "id", "result link"를 다룬다), 명령: `search arxiv "질의" [--max 100] [--since 2023]`, `import 파일.csv --source ieee|patent|other`, `stats`.

**테스트:** `test_insert_dedupes_by_doi_and_title`, `test_parse_arxiv_atom_fixture`, `test_import_ieee_csv_column_names_normalized`, `test_import_patent_csv`, `test_stats_counts_status_and_missing_abstract`, `test_cli_import_prints_utf8`.

## 작업 2: `paper_screen.py`

**인터페이스:** `make_batches(conn, run_root, n, per, year=None) -> (run_dir, n_agents)`(new이고 초록 있는 논문을 `agent_NN.json`으로 나눔. `_work/{YYYYMMDD_HHMMSS}/`), `verify(conn, run_dir) -> dict`(errors: 없는 id, 배치 밖 id, 잘못된 decision, 중복. warnings: 누락), `apply(conn, judgments_path, run_dir) -> dict`(status와 judgments 갱신), `stats(conn)`.

**스킬 paper-screen 절차:** 1. 기준서가 없으면 `templates/papers/selection_criteria.md`를 `papers/criteria/selection_criteria.md`로 복사하고 프로파일(`overview.md`의 문제 정의, `techniques.md`의 보유 기법)로 자리표시를 채운다 (사용자 검토 뒤 확정), 2. `paper_screen.py batch -n 100 --per 10`, 3. 에이전트 N명(`ai-assisted-dev:paper-reader`)에게 기준서와 자기 파일을 주고 `{id, decision, reason}` 목록과 기준 변경 제안을 받아 메인이 `judgments.json`으로 저장, 4. `verify`, 오류가 있으면 기록하지 않고 보고, 5. in과 out 수와 표본을 보고하고 사용자 확인 뒤 `apply` (자동 진행이면 바로), 6. 기준 변경 제안은 모아서 보고만 (기준서는 사용자가 고친다)

**테스트:** `test_batches_split_only_new_with_abstract`, `test_verify_catches_unknown_duplicate_and_bad_decision`, `test_apply_updates_status_and_records_reason`, `test_stats`.

## 작업 3: `paper_analyze.py`와 paper-reader 에이전트

**인터페이스:** `targets(conn, limit) -> list`(status in이고 analysis 없는 것. pdf 경로는 `papers/pdfs/{id 안전화}.pdf` 또는 `.txt`가 있으면 붙임), `extract_json_block(md_text) -> dict|None`(마지막 ```json 블록), `apply(conn, analysis_dir) -> dict`(md마다 JSON을 읽어 analysis 표에 넣고 status를 analyzed로. 깨진 것은 skipped 목록), `catalog(conn, out_path)`(분류표의 핵심 열로 정렬된 md 표: id, 제목, 연도, 이식성, 대상, 추천도, 핵심기여).

**에이전트 paper-reader:** description "논문 1편의 전문(PDF나 텍스트)과 프로젝트 프로파일만 읽고 정해진 양식(분류표, 알고리즘 요약, 모듈 대응, JSON)으로 분석을 돌려주는 읽기 전용 작업자. paper-screen(초록 판정)과 paper-analyze(전문 분석)가 부른다", tools Read, Grep, Glob. 본문: 본문 근거로만, 모르면 미상, 추측 금지, 그림과 표에만 있는 수치는 미상, 고정 선택지 밖의 값 금지, 파일 참조는 md 링크.

**양식 categories.md:** 공통(이식성 상|중|하, 관련성 직접|간접|낮음, 대상 decoder|encoder|both|design|other 를 일반화해 "대상 부품"은 프로파일 structure.md의 모듈 이름 중 하나 또는 other, 핵심기여 한 줄), 구현(HW설계 O|X, 검증수준 이론|시뮬|FPGA|ASIC|실측|미상, 복잡도, 병렬화, 처리량), 성능(성능향상 O|X|N/A, 개선영역, 반복감소, 지연), 추천도 상|중|하, 한계, 추가확인. 도메인 고유 열(부호종류 같은 것)은 "프로젝트 고유 열" 절에 프로파일에서 채운다.

**스킬 paper-analyze 절차:** 1. 기준 양식 셋이 `papers/criteria/`에 있는지, 프로파일 자리표시가 채워졌는지 확인, 2. `paper_analyze.py list -n 10`으로 대상과 전문 위치를 받는다 (전문이 없으면 `papers/pdfs/`에 두라고 안내. 사내 PC에서는 브라우저로 내려받는다), 3. 논문마다 paper-reader 에이전트에게 분석 지시(양식 analysis_prompt.md, categories.md, 프로파일 경로, 전문 경로)를 주고 결과 md를 `papers/analysis/{id}.md`에 저장 (병렬, 한 번에 5편 안팎), 4. `paper_analyze.py apply`, 5. `paper_analyze.py catalog`, 6. 이식성 상과 추천도 상인 논문을 idea-apply 후보로 보고

**테스트:** `test_targets_pick_in_without_analysis_and_attach_text_path`, `test_extract_json_block_last_block_and_broken_returns_none`, `test_apply_records_and_skips_broken`, `test_catalog_table_sorted_by_portability`.

## 작업 4: paper-search 스킬

절차: 1. `papers/`가 없으면 `paper_search.py init`으로 폴더와 README를 만든다, 2. 질의를 프로파일 overview의 문제 정의와 techniques의 기법 이름에서 뽑아 사용자에게 보인다, 3. arXiv는 `paper_search.py search arxiv "질의" --since 연도`, 4. IEEE Xplore와 Google Patents는 브라우저에서 질의를 넣고 결과를 CSV로 내보낸다 (Claude Code의 브라우저 도구가 있으면 스킬이 직접: 검색 페이지 열기, 질의 입력, 내보내기 누르기, 받은 파일 경로 확인. 없으면 사용자에게 절차를 안내하고 파일 경로를 받는다), 5. `paper_search.py import 파일 --source ieee`, 6. `stats`로 새 논문 수와 초록 없는 수를 보고. 라이선스로 받을 수 있는 전문은 `papers/pdfs/{id 안전화}.pdf`에 둔다
