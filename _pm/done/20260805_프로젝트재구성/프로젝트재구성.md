# 프로젝트 재구성 — LDPC_2 → LDPC_dev

> 작업일: 2026-08-05
> 발단: 구 저장소의 사용자 메모(프로젝트재구성.md, 아카이브에 보존)에서 제안된 재구성 방향을 논의 후 착수. git 저장소 신설 여부와 폴더 구성은 AI 판단에 위임됨

---

## 목적

성격이 다른 세 갈래의 작업을 프로젝트 단위로 분리하고, 누적된 관리 파일을 정리하여 새 저장소로 재출발한다.

---

## 배경

- ㉮ `0_LDPC_original/`은 외부에서 가져온 원본으로 일부 파일이 손상되어 빌드 불가, 완성 대상이 아닌 참조용
- ㉯ `1_LDPC_revised/`는 원본의 속도 최적화 작업 (확정분만 외부로 단방향 반영)
- ㉰ `2_LDPC_light/`는 논문 아이디어 스크리닝용 경량 Python 시뮬레이터
- ㉱ 구 저장소는 폐기된 Phase 계획(_pm), 과하게 상세한 분석 문서, 세 프로젝트가 한 `_pm/`에 섞인 TODO를 갖고 있었음

---

## 판단 (위임받은 결정)

- ㉮ **형제 폴더 신설 + 새 git 저장소** 선택. 구 저장소를 그대로 두고 필요한 것만 복사하는 방식이 이력 손실 걱정 없이 가장 안전함 (구 저장소 = 아카이브)
- ㉯ 폴더명은 사용자 제안대로 `LDPC_dev`
- ㉰ 프로젝트별 `_pm/` 분리 (1_LDPC_revised, 2_LDPC_light). 루트 `_pm/`은 저장소 공통 작업만
- ㉱ docs도 프로젝트 폴더로 이동 (speed_opt → 1_LDPC_revised/docs/, 2_LDPC_light 계획·리뷰 → 2_LDPC_light/docs/). 코드베이스 공용 문서(architecture, ADR, guide, style)는 루트 `docs/` 유지
- ㉲ Project 3 (논문 적용) 폴더는 지금 만들지 않음. 2_LDPC_light가 외부 파라미터로 동작하는 시점에 신설 (루트 TODO에 등록)
