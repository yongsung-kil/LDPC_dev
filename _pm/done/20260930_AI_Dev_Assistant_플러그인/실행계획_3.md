# AI_Assisted_Dev 플러그인 실행 계획 (3단계: 대시보드와 HTML 작성 가이드)

> 작성: 2026-09-30
> 설계: [20260929_AI_Assisted_Dev_플러그인.md](20260929_AI_Assisted_Dev_%ED%94%8C%EB%9F%AC%EA%B7%B8%EC%9D%B8.md) 6절(대시보드 자료 양식과 화면 구성), 판정요청 물음 3(HTML 작성 가이드 새로 씀)과 4(카드를 태스크 문서로 연결)
> 공통 제약은 1단계 계획과 같다. 이 계획은 파일, 인터페이스, 파싱 규칙, 테스트 이름과 단언을 적고 코드는 저장소에 바로 쓴다 (테스트 먼저). 판단: 코드를 계획과 저장소에 두 번 쓰지 않는다
> 판단: md를 html로 바꾸는 데 외부 패키지(`markdown`)를 쓰지 않고 표준 라이브러리만으로 작은 변환기를 둔다. 플러그인은 설치 없이 돌아야 하고, 대시보드가 다루는 md는 제목, 문단, 목록, 표, 코드 울타리, 링크, 강조, 인용, 머리말이면 충분하다

**목표:** 프로젝트 루트에서 대시보드 스킬을 돌리면 `dashboard/index.html`(진행 중 작업 카드, 결정 대기, 최근 완료, 아이디어 현황, 최근 실험, 문서 지도)과 문서별 html이 생기고, 왼쪽 사이드바(접기), 위 검색, 오른쪽 "이 페이지의 차례"가 붙은 정적 사이트가 상대 링크만으로 열린다. `docs/html_guide.md`가 이 규격의 정본이다.

## 검토 초점

- 1. `_pm/`이 없거나 비어 있는 프로젝트에서도 대시보드가 빈 칸으로 생긴다 (죽지 않는다) (작업 2, 3)
- 2. 한글 경로와 파일 이름을 가진 md의 html 링크가 퍼센트 인코딩으로 열린다 (작업 3)
- 3. 코드 울타리 안의 `<`와 `&`가 html로 새지 않는다 (작업 1)
- 4. 표 칸 안의 `<br>`과 인라인 코드가 그대로 보인다 (작업 1)
- 5. 두 번 돌려도 산출물이 같다 (생성 시각 줄만 다름) (작업 3)

## 파일 구조

```
plugin/scripts/md_to_html.py        표준 라이브러리 md 변환기: parse_frontmatter, md_to_html, extract_headings
plugin/scripts/collect_status.py    프로젝트를 훑어 dashboard/status.json
plugin/scripts/render_dashboard.py  status.json과 md로 dashboard/index.html, dashboard/docs/**/*.html, 깨진 링크 보고
plugin/skills/dashboard/SKILL.md
plugin/templates/dashboard/config.json   선택 설정 (아이디어 표 파일, 실험로그 파일, 문서 폴더 목록)
docs/html_guide.md                  (새 저장소 루트) HTML 작성 가이드
tests/test_md_to_html.py, test_collect_status.py, test_render_dashboard.py
dashboard/                          (새 저장소 자신의 대시보드, 산출물. 추적한다)
```

## 작업 1: `md_to_html.py`

**인터페이스:** `parse_frontmatter(text) -> (meta: dict, body: str)` (머리말 `---` 사이의 `key: value`와 `key: [a, b]`), `md_to_html(body, link_rewrite=None) -> str` (link_rewrite는 href를 바꾸는 함수), `extract_headings(body) -> list[(level, text, anchor_id)]`, `slug(text) -> str` (제목 id. 한글 유지, 공백은 붙임표).

**지원 문법:** `#`부터 `####` 제목, 문단, `-`와 `1.` 목록(들여쓰기 2칸 단위 중첩), `- [ ]`와 `- [x]`(☐ ☑로), `|` 표(첫 줄 머리, 둘째 줄 구분), 코드 울타리(백틱과 물결표, 안은 escape), 인라인 코드, `**굵게**`, `*기울임*`, 링크 `[t](u)`(u가 .md면 link_rewrite 적용), `>` 인용, `---` 가로줄, `<br>`은 표 칸에서 그대로.

**테스트 (`tests/test_md_to_html.py`):**
- `test_frontmatter_parsed_and_removed`: `---\ntitle: 개요\ntags: [a, b]\n---\n# 제목\n` → meta {"title": "개요", "tags": ["a", "b"]}, body가 `# 제목`으로 시작
- `test_headings_get_ids_and_toc`: `## 첫 절\n### 둘째 절` → html에 `<h2 id="첫-절">`, extract_headings == [(2, "첫 절", "첫-절"), (3, "둘째 절", "둘째-절")]
- `test_fenced_code_is_escaped_and_not_parsed`: ```` ```\na < b & **c**\n``` ```` → `<pre><code>a &lt; b &amp; **c**</code></pre>`
- `test_table_keeps_br_and_inline_code`: 표 두 줄 → `<table>`, 칸에 `<br>`과 `<code>x</code>`
- `test_lists_nested_and_checkboxes`: `- a\n  - b\n- [x] c\n- [ ] d` → 중첩 `<ul>`, ☑ c, ☐ d
- `test_links_rewritten_only_for_md`: `[a](b.md) [c](https://x)` with rewrite → `href="b.html"`, https 그대로
- `test_paragraph_and_inline_marks`: `굵게 **a** 코드 \`b\` 기울임 *c*` → `<strong>a</strong>`, `<code>b</code>`, `<em>c</em>`

## 작업 2: `collect_status.py`

**인터페이스:** `collect(root, config=None) -> dict`, `main(argv)` (`dashboard/status.json`에 씀, ensure_ascii=False, indent 1).

**status.json 꼴:**
```
{"generated": "YYYY-MM-DD HH:MM:SS", "project": 이름,
 "todo": [{"title", "done": bool, "detail": 경로|null, "subtasks": [{"title", "done"}], "notes": [..]}],
 "done": [{"date", "title", "summary"}],
 "decisions": [{"file", "title", "questions": [{"no", "title", "answered": bool}]}],
 "ideas": [{"no", "title", "source", "status", "dir"}],
 "experiments": [{"file", "title"}],
 "docs": [{"path", "title", "tags": [..], "links_out": [경로..], "links_in": [경로..]}],
 "profile": {"exists": bool, "files": [..]}}
```

**파싱 규칙 (설계 6절 표):** TODO는 `_pm/TODO.md` "작업 목록" 절의 `- [ ]`와 `- [x]` 최상위 항목, 그 아래 2칸 들여쓴 `- [ ]`(하위 단계), `- 상세: 경로`, 그 밖의 줄은 notes. DONE은 `_pm/DONE.md`의 `### YYYY-MM-DD 제목` 절과 다음 비어 있지 않은 줄(요약). 판정요청은 `_pm/tasks/**/판정요청*.md`의 `## 물음 N. 제목`과 그 뒤 첫 `%` 줄(내용이 `%`뿐이면 미답). 아이디어는 설정의 `ideas_files`(기본: 루트와 한 단계 아래의 README.md)에서 머리 칸에 `#`, `제목`, `상태`가 모두 든 표. 실험은 설정의 `experiment_logs`(기본: 이름이 `실험로그.md`인 파일)의 `## ` 절. 문서는 설정의 `doc_dirs`(기본: `docs`, `_wiki`, `_pm`, 루트의 README.md와 CLAUDE.md)의 모든 md. 제목은 머리말 title, 없으면 첫 `# `, 없으면 파일 이름. 링크는 md 링크 중 .md를 가리키는 것만, 퍼센트 디코딩과 정규화 뒤 프로젝트 기준 상대 경로. `links_in`은 전체를 모은 뒤 계산. 제외 폴더는 onboard_init과 같다.

**테스트 (`tests/test_collect_status.py`):** tmp 프로젝트에 `_pm/TODO.md`(항목 2, 하나는 하위 단계 3개 중 1개 완료와 상세 링크), `_pm/DONE.md`(절 2), `_pm/tasks/t/판정요청_x.md`(물음 2, 하나만 답), 루트 README.md(아이디어 표 2줄), `docs/실험로그.md`(절 2), `docs/a.md`(머리말 tags, b.md 링크), `docs/b.md`
- `test_todo_items_with_subtasks_and_detail`
- `test_done_sections`
- `test_decision_questions_answered_flag`
- `test_ideas_table_and_experiment_sections`
- `test_docs_links_out_and_in_with_korean_names`
- `test_empty_project_gives_empty_lists`
- `test_main_writes_status_json_utf8`

## 작업 3: `render_dashboard.py`

**인터페이스:** `render(root, status) -> list[str]` (만든 파일 목록), `check_links(root) -> list[(html, href)]` (dashboard/ 안의 상대 href가 가리키는 파일이 없는 것), `main(argv)` (collect를 부르고 render, 깨진 링크를 출력하고 있으면 1).

**산출:** `dashboard/index.html`, `dashboard/docs/{md 상대 경로}.html`(문서마다. 경로의 한글은 퍼센트 인코딩해 href에 씀), `dashboard/assets/style.css`, `dashboard/assets/app.js`, `dashboard/assets/search.json`(제목, 경로, 본문 앞 2000자).

**화면 (설계 6절 ㉱, html_guide.md 규격):** 왼쪽 사이드바에 큰 장(대시보드, 작업, 결정, 아이디어, 실험, 문서)과 작은 장(문서는 폴더별), 장마다 접었다 펴기(details 요소), 위에 검색 상자(app.js가 search.json을 읽어 제목과 본문 검색, 결과 목록), 오른쪽에 "이 페이지의 차례"(extract_headings), 가운데 본문. index.html의 칸: 진행 중 작업 카드(제목, 하위 단계 진행률 막대, 상세 문서로 가는 링크), 결정 대기(미답 물음 수와 링크), 최근 완료 5건, 아이디어 현황 표, 최근 실험 5건, 문서 지도(문서별 들어오는 링크 수, 고아 문서 표시). 색과 글꼴은 css 변수, 어두운 모드는 prefers-color-scheme. 외부 자원 없음.

**테스트 (`tests/test_render_dashboard.py`):** 작업 2의 tmp 프로젝트에 render
- `test_index_has_cards_for_open_todo_with_progress`: 진행 중 카드에 제목과 "1/3"
- `test_docs_rendered_with_percent_encoded_hrefs`: `dashboard/docs/docs/a.html` 존재, index의 문서 지도 href가 퍼센트 인코딩
- `test_sidebar_groups_and_toc_present`: `<details>` 장 6개, 문서 페이지에 `이 페이지의 차례`와 h2 id
- `test_check_links_reports_missing_target`: 있는 html에 없는 href를 넣으면 보고
- `test_render_is_deterministic_except_generated_line`: 두 번 돌린 index.html이 생성 시각 줄을 빼면 같다
- `test_empty_project_renders_empty_dashboard`
