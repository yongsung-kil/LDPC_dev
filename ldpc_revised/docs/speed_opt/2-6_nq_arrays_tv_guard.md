# 2-6. `_nq` 배열 체인을 TV 전용으로 가드

| 항목 | 내용 |
|------|------|
| 상태 | **적용 완료** (일괄 진행) |
| 파일 | `ldpc_revised/decoder.h`, `decoder.cpp` |
| bit-exact | 보장 (Ref-C에서 dead data 생산 제거) |
| 위험도 | 낮음 |

## 왜 해야 하나

`VNU_out_nq` / `VNU_out2_nq` / `VNU_out3_nq`(양자화 전 V2C 값의 3단 파이프라인 지연 사본)의 데이터 흐름을 전수 추적하면:

- 쓰기: VN_Cal 계열 4곳(`= temp_nq`) + VN_Cal_Pre 계열 4곳(`= VNU_out[...]`)
- 이동: `Delay_2clk()`에서 clk마다 3단 시프트 복사 (J×z_sb×2)
- **최종 소비: `check_in_before_BS_nq` → tv 버퍼 쓰기 (TV 전용, 2-5에서 가드됨) 하나뿐**

Ref-C에서는 쓰기 8곳 + clk당 ~1,088 int 복사 + 배열 3개 할당이 전부 결과에 기여하지 않는다.

## 무엇을 어떻게 바꿨나

선언(decoder.h) / NULL 초기화 / 할당 / 해제(2곳) / `Delay_2clk()` 시프트 복사 2줄 / 쓰기 8곳을 전부 `#if defined (__ECC_TV__)`로 가드. TV 빌드는 기존과 완전 동일.

로컬 `temp_nq` 계산 자체는 남겨둠 — 레지스터 대입 1회 수준이라 비용이 없고, 가드하면 양자화 분기 내부까지 손대야 해서 diff가 커짐.

## 검증

grep `VNU_out*_nq` 전 occurrence(-B1) → 15곳 모두 `#if defined (__ECC_TV__)` 블록 내부 확인. `tv_new_sgn_mag_HCU_in*_nq` 계열은 원래부터 TV 버퍼(기존 가드 내부)라 대상 아님.

## 다른 버전 코드에서 위치 찾는 법 (이식 앵커)

1. `_nq` 접미사 배열을 전역 검색 → 쓰기/시프트/읽기 전 지점의 데이터 흐름을 그린다
2. **최종 소비처가 TV 출력뿐인지 반드시 전수 확인** — Ref-C 경로 소비처가 하나라도 있으면 가드 금지
3. 선언·할당·해제·시프트·쓰기를 같은 매크로로 일괄 가드 (하나라도 빠지면 TV 빌드에서 미할당 접근)
