## ㉮ 가설 목록

### R2-3 (구간 번호의 뜻이 파서와 디코더에서 다르다)

- ㉠ 사실 가설 A: 분기가 iteration 5~8 구간에만 있는 파일에서 [code_diff 3.2](../../code_diff.md#ch3) 파서는 그 구간을 span 0으로 번호 매기고, [code_diff 4.1](../../code_diff.md#ch4)과 [5.1](../../code_diff.md#ch5)은 span 0을 iteration 1~4로 못박아 문턱 130을 쓴다. 그 결과 BF 진입 프레임은 5~8의 분기를 문턱 130으로 고르고, BF 미진입 프레임은 `cur_sw_branch_idx[0]`이 0에 고정되어 분기 2가 어떤 프레임에서도 선택되지 않으며 오류 출력도 없다
- ㉡ 처방 가설 A1 (갈래 ㉮): 파서가 구간별 `iter_start`를 `PARAM_LLR`에 기록하고 `Select_BF`가 그 범위로 문턱 배열을 고르면 문제가 해결되고 새 문제가 생기지 않는다
- ㉢ 처방 가설 A2 (갈래 ㉯): 파서가 구간 0의 시작이 1이 아니면 오류를 내면 문제가 해결되고 새 문제가 생기지 않는다

### R2-7 (iteration 1~4 분기 존재와 문턱 130)

- ㉠ 사실 가설 E: `syn_th_BF1`(130)은 선언과 대입뿐이고 읽는 곳이 없으며 `FLAG_HD_1_4_SET_TYPE_1`을 대입하는 코드가 없고, 배경 메모는 iteration 1~4를 분기 없음으로 적으며, 파일은 그 구간에 분기 둘을 둔다. 따라서 [code_diff 5.1](../../code_diff.md#ch5)이 syn_weight 130을 iteration 1~4의 분기 경계로 쓰는 것은 근거가 없는 새 동작이고 상위 7장 미결정에 없다
- ㉡ 처방 가설 E1: 상위 [7장](../../20260902_SW_branch_LLR_matrix.md)에 Decision 항목을 추가하고 사용자 결정을 받으면 문제가 해결되고 새 문제가 생기지 않는다

### R2-9 (파일의 분기 개수와 상수 `num_sw_branch[]` 대조 부재)

- ㉠ 사실 가설 C: [code_diff 4.1](../../code_diff.md#ch4)의 default 갈래가 `num_sw_branch[0] = 1`로 두므로 `matrix_sel`이 `LAYOUT_PRIME_512B_TLC_VSS_OFF`가 아니면 `Select_SW_Branch(0, weight)`가 항상 0을 돌려주고 iteration 1~4 구간의 분기 1 그룹이 어떤 프레임에서도 후보가 되지 않으며 오류 출력도 없다. 이 조합은 AUTO 빌드에서 `main.cpp:141` 경로로 도달 가능하다
- ㉡ 처방 가설 C1 (갈래 ㉮): 파서가 구간별 분기 수를 세어 기록하고 `Init_Dec_Option` 끝에서 `num_sw_branch[]`, `num_sw_span <= MAX_SW_SPAN`, 문턱의 양수 오름차순을 대조해 어긋나면 멈추면 문제가 해결되고 새 문제가 생기지 않는다
- ㉢ 처방 가설 C2 (갈래 ㉯): 파서가 세어 `num_sw_branch[]`를 직접 채우면 문제가 해결되고 새 문제가 생기지 않는다

### R2-10 (첫 분기 그룹 index가 0이 아니면 span이 -1)

- ㉠ 사실 가설 B: 첫 분기 그룹의 index가 0이 아닌 헤더에서 3.2 파서가 `sw_span_idx_each_group`에 -1을 쓰고 [code_diff 6.1](../../code_diff.md#ch6)이 `cur_sw_branch_idx[-1]`을 첨자로 읽는다. 구 형태 파일 `Prime_ECC_2.4/Initial_LLR_matrix/LLR_MATRIX_0.txt`를 3.2 파서에 넣으면 분기 줄이 `1 2 31`로 읽혀 실제 사례가 된다
- ㉡ 처방 가설 B1: 3.2에 세 검사(첫 분기 그룹 index가 0이 아니면 오류, 같은 구간 안 index 역행 오류, `num_sw_span > MAX_SW_SPAN` 오류)를 넣고 6.1에 `span < 0 || span >= MAX_SW_SPAN` 방어를 두면 문제가 해결되고, 배경 메모 예시(`-1 0 1 2 -1`)는 오류 없이 통과한다

### R2-11 (순서 독립성 서술이 실제 범위를 넘는다)

- ㉠ 사실 가설 D: 6.1 수정 후 루프는 `g = num_group - 1`부터 내려가며 첫 일치에서 `break`하므로, 후보 집합 안에서 iteration 범위가 겹치면 뒤쪽 그룹이 이긴다. 같은 분기 안 겹침과, iteration 1~8을 통째로 덮는 분기 없는 그룹과 5~8 분기 그룹의 공존 두 경우에서 배치를 뒤집으면 결과가 바뀐다. 수정 전 AUTO 갈래도 같은 성질이므로 새 결함은 아니다
- ㉡ 처방 가설 D1: 문서에 전제(한 분기의 그룹들과 분기 없는 그룹을 합친 집합 안에서 iteration 범위가 겹치지 않는다)를 적고 파서에 구간별, 분기별 범위 겹침 검사를 넣으면 문제가 해결되고 새 문제가 생기지 않는다

### R2-16 (restart 지점이 iteration 1~4에 있으면 미진입 프레임이 건너뛴다)

- ㉠ 사실 가설 F: `ITER_MAX_HBF`가 4가 되면 BF 미진입 프레임의 mn 수열이 0, 5, 6, ...이 되고, [code_diff 8.1](../../code_diff.md#ch8)이 `iter == restart_iter[i]`를 그대로 비교하므로 `restart_iter`가 1 이상 4 이하이면 미진입 프레임만 restart edge clear를 놓친다
- ㉡ 처방 가설 F1: 파서가 `restart_iter[i] <= ITER_MAX_HBF`를 오류로 잡거나 문서에 제약을 적으면 문제가 해결되고 새 문제가 생기지 않는다
