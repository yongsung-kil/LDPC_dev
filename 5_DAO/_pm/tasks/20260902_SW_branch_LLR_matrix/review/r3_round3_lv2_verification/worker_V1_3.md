**두 경우 모두 결과는 row 0이다.** 곧 iteration 125~128은 오류 출력을 내면서 파일의 첫 row 파라미터로 복호를 이어간다. R2-15의 "오류 경로로 빠진다"는 주장이 맞고, 뒤이어 row 0으로 복호가 이어지는 것도 맞다.

### E3-9 (처방 검증): 식별자를 고쳤을 때 1.5SD 프레임의 동작 (확인됨)

`Select_BF`의 1.5SD 갈래 [decoder.cpp:2113-2128](../../../../../../0_LDPC_original/src/decoder.cpp)은 2114-2115행에서 `mn = mn + ITER_MAX_HBF`, `MN = MN + ITER_MAX_HBF`를 한다. 곧 HD 미진입 갈래(2097-2098)와 미는 양이 똑같이 4다. code_diff 5.1 수정 후 코드도 574-575행에서 같은 두 줄을 유지한다. `Select_BF`는 1.5SD에서 `MN[]` 배열 자체는 건드리지 않는다.

**보정이 1.5SD에 걸리지 않을 때** (`MN[123] = 124`)

- ㉮ 1118행: `MN = 124`
- ㉯ `mn = 0` 본문 뒤 `Select_BF` 1.5SD 갈래 → `mn = 4`, `MN = 128`
- ㉰ 증가식 뒤 `mn = 5`. 수열은 5, 6, ..., 128
- ㉱ iteration 125~128 네 번이 파일 범위 밖이라 E3-8과 같은 오류 경로로 빠진다

**보정이 1.5SD에 걸릴 때** (`MN[123] = 120`)

- ㉮ 1118행: `MN = 120`
- ㉯ `Select_BF` 1.5SD 갈래 → `mn = 4`, `MN = 124`
- ㉰ 증가식 뒤 `mn = 5`. 수열은 5, 6, ..., 124
- ㉱ 모든 iteration이 파일 범위(1~124) 안이다. 실행 iteration 수는 120

곧 조건에 1.5SD를 넣으면 1.5SD 프레임의 범위 초과가 사라진다. 처방이 HD 하나만 고치는 것이 아니라 1.5SD의 같은 결함까지 함께 없앤다.

### E3-10 (처방 검증): 1.5SD에 보정이 걸리는 것이 의도인지 (확인됨, 소스에 단서 있음)

비AUTO 갈래의 대응 코드가 결정적 단서다. [main.cpp:704-781](../../../../../../0_LDPC_original/src/main.cpp)의 `Set_Ref_C_Iteration`은 `#ifndef __AUTO_LLR_OPT__` 안에서 `MN[]`을 직접 채운다.

- ㉮ HD (709-725행): `MN_num = ITER_MAX_REF_C_HD_NUM`(5), `MN[0] = ITER_MAX_HBF`(4), `MN[4] = ITER_MAX_HD_PRIME`(120)
- ㉯ 1.5SD (768-772행): `MN_num = ITER_MAX_REF_C_1_5SD_NUM`(1), `MN[0] = ITER_MAX_HD_PRIME`(120)

이 값으로 비AUTO를 손 실행하면,

- ㉠ HD 진입 프레임: `MN = MN[4] = 120` → `mn`은 1~120 (120회)
- ㉡ HD 미진입 프레임: `MN = 120` → `Select_BF`가 `+4` → `MN = 124` → `mn`은 5~124 (120회)
- ㉢ 1.5SD 프레임: `MN = MN[0] = 120` → `Select_BF`가 `+4` → `MN = 124` → `mn`은 5~124 (120회)

곧 비AUTO 원본에서 세 경우 모두 실제 iteration 수가 120이고, 미진입 프레임과 1.5SD 프레임은 똑같이 `mn` 124에서 끝난다. AUTO에서 이 수열을 그대로 재현하려면 `MN[MN_num-1]`이 120이어야 하고, 그러려면 파일에서 읽은 124에서 4를 빼는 보정이 HD와 1.5SD **양쪽에** 걸려야 한다. `MN[0] = ITER_MAX_HBF`(4)도 비AUTO HD의 `MN[0] = ITER_MAX_HBF`와 똑같은 값이다.

주변 주석에는 단서가 없다 (124-131 블록에 주석이 하나도 없다). 그러나 위 대응 코드가 "1.5SD도 보정을 받아야 비AUTO와 같은 iteration 수열이 된다"를 명확히 보이므로, 1.5SD를 조건에 넣는 것이 의도이며 지금 이름이 손상이라고 판단할 근거가 소스 안에 있다.

보조 근거: `Select_BF`에서 `mn`과 `MN`을 4씩 미는 두 갈래는 HD 미진입(2097-2098)과 1.5SD(2114-2115)뿐이고, `iter_num -= ITER_MAX_HBF` 보정([decoder.cpp:1974-1978](../../../../../../0_LDPC_original/src/decoder.cpp))도 조건이 `MODE_DEC_HD || MODE_DEC_1_5SD`다. `MN[]`을 미는 쪽만 HD 단독으로 두면 세 곳의 조건 집합이 어긋난다.

### E3-11 (처방 검증): 조건의 구성과 식별자 수정이 바꾸는 모드 집합 (확인됨)
