글로벌 규칙 "용어를 임의로 줄이거나 만들지 않기"에 걸린다. 특히 209행은 코드 블록 밖의 문장이고, `TYPE_1`은 `FLAG_HD_1_4_SET_TYPE_1`과 `FLAG_HD_5_8_SET_TYPE_1` 둘 다에 있어 짧은 이름만으로는 어느 쪽인지 정해지지 않는다. code_diff는 591행에서 `FLAG_HD_1_4_SET_TYPE_0` 전체 이름을 쓴다. 처방: 원 이름으로 쓰고, 203-206행 블록은 B ㉴대로 표로 바꾼다.

### I.3 표 칸 안 `\|` 이스케이프 (㉰)

상위 283행 "`iter == 0 \|\| iter == 1 \|\| iter == ITER_MAX_HBF + 1`": GFM 표 규격은 코드 스팬 안이라도 `|`를 `\|`로 이스케이프하도록 하고 렌더링 때 역슬래시를 지우므로 GitHub와 VSCode(markdown-it) 모두 `iter == 0 || iter == 1 || …`로 나온다. 문제 없음.

### I.4 구어체 (㉱)

상위 176 "여기가 축이다", 199 "못박아 두었다", 358 "못박을지", code_diff 591 "못박았다": 문서체 규칙에 구어체 금지 조항이 없으므로 지적하지 않는다. 참고로 "못박다"는 표준 표기가 "못 박다"(띄어쓰기)이며, 규칙 항목이 아니므로 판정에 넣지 않는다.
