## 참고 관찰 (결론 아님, 선택)

관점을 정하다가 눈에 띈 것만 짧게 적는다. 확인이 끝난 결론이 아니므로 Round 2에서 따로 검증해야 한다.

- ㉮ `README.md`가 설명하는 `effective_FERs` 필드, `ExitAfterInitialMatrixMode` 열거형, `TIME_CONFIG.MAX_STAGE_TIME_SECONDS` 설정은 현재 코드에 `grep`으로 잡히지 않는다. 코드에는 각각 `FERs`와 `FERs_partial`, `RunDAOMode`, `MAX_STAGE_TIMEOUT_SECONDS`가 있다. README의 파일 링크도 전부 `DAO/SRC/...` 옛 경로를 가리킨다
- ㉯ `DAO_CONFIG.Gen_LLR_Mode_HBF_SEQUENCE`의 값 `[7, 8, 1, 2, 12]`는 `GenLLRMode` 열거형에 없는 번호다. `Set_Gen_Trial_LLR_Mode`는 선택한 값을 `GenLLRMode(selected_mode).name`으로 바꾸므로 `IS_HBF_OPT`가 참인 경로가 실제로 쓰이는지 확인이 필요하다
- ㉰ `Copy_Uncors`는 `test_mode` 인자를 받지만 본문에서 쓰지 않는다. 문서화된 Two-stage 디렉토리 분기(README 3.2.4의 `Partial`, `Full` 하위 디렉토리)와 현재 본문의 경로 계산이 다르다
- ㉱ `TIME_CONFIG.MPI_COMM_TIMEOUT_SECONDS`의 실제 값은 1200초인데 주석은 "1시간 이상이면 타임아웃 없음"이라고 적혀 있고, `MPI_Barrier`만 `max(값, 3600)`으로 올려 쓴다
- ㉲ `DAO_Constants.py`의 `TEST_MODE_DIR_NAME`에는 `TestMode.PARTIAL` 항목만 있고 `TestMode.FULL` 항목이 없다. README 3.2.4의 예시 코드는 두 값이 모두 있다고 적는다
- ㉳ `Is_LLR_Valid`의 CSW 검사는 `prev_CSW <= current_CSW`를 실패로 보아 같은 값을 금지하는데, `DAO_spec.md` C5는 non-increasing(같은 값 허용)이라고 적는다
- ㉴ `Print_Config`와 `Print_Configs`의 본문이 같고, `CONFIGS` 목록에 `HBF_OPT_CONFIG`가 들어 있는데 이 클래스는 `__init__`에서 `DAO_CONFIG.IS_HBF_OPT`를 바꾸는 부수효과를 가진다
- ㉵ `ReorderState` docstring이 설명하는 `total_rounds`, `round_best_FER`, `round_best_avg_iter` 필드는 dataclass 정의에 없다
- ㉶ 로그 문구에 줄표(em dash)와 이모지, 장식 막대가 섞여 있다(예: `Periodic Speed Test` 문구, `✓ New round best`, `══` 막대). 프로젝트 문장 규칙과 대조가 필요하다
- ㉷ `Util/check_result_files.py`의 대상 경로가 빈 문자열이라 그대로는 오류 메시지만 내고 끝난다. `Util/remote_server_sync.py`는 접속 정보를 본문에 적어 두는 구조다
