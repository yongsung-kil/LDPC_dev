## 참고 관찰 (결론 아님)

㉮ 검사 스크립트 두 벌을 다시 돌렸고 둘 다 `FAILED: none`이었다 (`check_sw_branch.py` 40건, `check_dao_fixes.py` 20건).

㉯ 예시 파일 1을 읽어 직접 뽑은 값은 설계 2.1 표와 같았다. 분기 index `[0, 0, 1, 0, 1, 1, -1 * 6]`, 묶음 `{0,1}, {2}, {3}, {4,5}`와 나머지 홑그룹, 구간 `(1, 4, 2분기)`와 `(5, 8, 2분기)`, `max_iteration` 124.

㉰ 같은 파일로 `Initialize_Stage`와 같은 계산을 돌리면 `INITIAL_TARGET_GROUP_IDX`가 0이든 1이든(1이 현재 기본값) 타겟 목록은 `[0, 2, 3, 4, 6, 7, 8, 9, 10, 11]`이 되고, `Check_SW_Branch_Mode_Allowed`는 타겟 0과 3에 대해 "DAO updates only the last branch"를 돌려준다.

㉱ `current_target_bundle`은 bcast 튜플에 실려 오지만 쓰이는 곳은 `Print_Mode_Target_Info`의 로그 한 줄뿐이다. 실제 변이 대상은 `_Get_Target_Bundle_Groups`가 trial 매트릭스에서 다시 계산한다.

㉲ `bundle_of_group`의 원소들은 같은 묶음이면 같은 리스트 객체를 가리킨다 (`current_bundle`을 그대로 대입한다).

㉳ `Gen_LLR_Gen_Initial_Group`의 `floor_flag` 기본값은 아직 0이다 ([DAO_Main.py:3666](5_DAO/SRC/DAO_Main.py#L3666)). 단일 row 후보 생성 자리만 `SW_BRANCH_NONE`으로 바뀌었다.

㉴ restart 그룹을 만드는 두 자리는 앞 그룹 또는 첫 그룹의 `floor_flag`를 물려받고 헤더에는 1 또는 0을 적는다 ([DAO_Main.py:5937](5_DAO/SRC/DAO_Main.py#L5937), [DAO_Main.py:6309](5_DAO/SRC/DAO_Main.py#L6309)).

㉵ `Gen_LLR_Insert_Restart_Group`은 삽입 뒤 모든 그룹의 iteration을 1부터 다시 매긴다 ([DAO_Main.py:5946](5_DAO/SRC/DAO_Main.py#L5946)).

㉶ `_Protected_Groups_Changed`는 row의 값, iteration, CSW, 분기 index만 비교하고 헤더 배열과 `restart_groups`는 비교하지 않는다.
