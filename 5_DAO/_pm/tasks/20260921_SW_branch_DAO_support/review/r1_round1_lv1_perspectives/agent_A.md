## 참고 관찰 (결론 아님)

- ㉮ `Build_SW_Branch_Layout`은 배치가 규칙에 어긋나면 이유를 돌려주는데 이를 받는 곳은 `Is_LLR_Valid` 하나다. `Read_Input_LLR_Matrix`, `Initialize_Stage`, `_Get_Target_Bundle_Groups`, `Check_SW_Branch_Mode_Allowed`, `_Protected_Groups_Changed`는 반환값을 받지 않는다
- ㉯ 타겟 목록을 묶음 대표로 접는 코드는 `Initialize_Stage`에만 있다. `Initialize_LLR_Matrix`와 optimal 갱신 뒤 복원은 `range(INITIAL_TARGET_GROUP_IDX, 그룹 수)`를 그대로 쓴다
- ㉰ `_Protected_Groups_Changed`는 row만 비교하고 헤더 배열은 비교하지 않는다. `Gen_LLR_Reorder_Group`은 `type_each_group`을 다시 만든다
- ㉱ `Check_Barrier_Sync` 안의 allgather는 `_safe_allgather`를 쓰지 않고 기본 타임아웃으로 돈다
- ㉲ `Gen_LLR_Gen_Initial_Group`의 꼬리 기본값은 아직 0이다. GEN_SINGLE_ROW 쪽만 `SW_BRANCH_NONE`으로 바뀌었다
- ㉳ 직접 돌려 본 결과 `LLR_MATRIX_1.txt`의 분기 index는 0, 0, 1, 0, 1, 1과 나머지 -1이고, 묶음은 (0, 1), (2), (3), (4, 5)와 나머지 홑그룹, 구간은 (1, 4, 2분기)와 (5, 8, 2분기)로 설계 2.1 표와 같았다. 이 파일에는 restart 그룹이 없다(`num_restart`가 0). restart가 섞인 분기 매트릭스는 저장소 입력에 없다
- ㉴ `check_sw_branch.py` 40건은 모두 PASS였다 (2026-09-22 실행)
