ECC_VER "2.4" 분기와 그 밖의 분기 모두 12번 자리에서 같은 교체가 되어 있고, 호출은 `ch_idx=0` 한 자리뿐이다 ([DAO_Main.py:9175](5_DAO/SRC/DAO_Main.py#L9175)). 모든 rank가 같은 시드를 받아야 속도 비교가 성립하므로 처방이 맞다
- ㉱ `Is_Matrix_Better`의 inf 치환 ([DAO_Main.py:2588](5_DAO/SRC/DAO_Main.py#L2588))은 대칭이다. `_Fill_Untested_Channels`가 미테스트 채널에 FER 1.0과 `avg_iterations` -1.0을 넣으므로 ([DAO_Main.py:1195](5_DAO/SRC/DAO_Main.py#L1195)) 음수는 미테스트 표시뿐이고, 양쪽 모두 inf이면 `Is_List_A_Strictly_Better`가 `le_all=True, lt_one=False`로 False를 낸다. partial 갈래는 `FERs_partial`만 견주고 `avg_iterations_partial`을 쓰지 않으므로 같은 처방이 더 필요하지 않다
- ㉲ REORDER trial 수 식 ([DAO_Main.py:8540](5_DAO/SRC/DAO_Main.py#L8540))이 `Init_Reorder_Group_Mode`의 `total_trials`와 같아졌다. 양쪽 모두 `target_group_indices`를 돌며 범위 밖과 restart 그룹을 빼 개수 n을 세고, HD는 `1 + sum(range(n, 0, -1)) + 1`, SD는 `1 + sum(range(n, 0, -1)) * 2 + 1`이다. `Init_Reorder_Group_Mode`는 `max_modification_trial`을 따로 쓰지 않으므로 루프를 도는 값은 `Set_Gen_Trial_LLR_Mode`가 정한 쪽 하나다. 묶음 접기로 목록이 묶음 대표만 담게 되어도 두 자리가 같은 목록을 보므로 어긋나지 않는다
- ㉳ C2(`Initialize_Stage`에서 `Set_Gen_Trial_LLR_Mode`를 타겟 목록 갱신 뒤로 옮긴 것, [DAO_Main.py:2320](5_DAO/SRC/DAO_Main.py#L2320))는 stage 번호 대 타겟 순환을 바꾸지 않는다. 타겟 자리는 `sequence_cycle_count = (stage_idx - 1) // len(모드 시퀀스)`로 정해지고 목록 갱신은 이 값을 건드리지 않는다. 바뀌는 것은 `current_target_group_list_index`가 어느 목록 위에서 계산되는가뿐이고, 교체 뒤에는 이번 stage의 목록을 본다. 목록 갱신 블록은 `current_gen_trial_LLR_mode`를 읽지 않으므로 앞으로 당겨도 값이 없어 생기는 문제가 없고, restart 건너뛰기 루프는 여전히 모드가 정해진 뒤에 돈다

### P12 타겟 목록의 묶음 단위가 모든 생성 자리에 적용되는가

- ㉮ `current_target_group_idx`가 묶음의 둘째 그룹을 가리켜도 판정과 변이가 달라지지 않는다. `_Get_Target_Bundle_Groups`는 `bundle_of_group[target_group_idx]`를 그대로 돌려주는데 묶음 구성원은 모두 같은 리스트를 가리키고 ([DAO_LLR_MATRIX.py:212](5_DAO/SRC/DAO_LLR_MATRIX.py#L212)), `Check_SW_Branch_Mode_Allowed`가 보는 `span_of_group`과 `group_branch_idx`도 묶음 안에서 같은 값이다. 둘째 그룹이 타겟이 되는 경로는 `Set_Gen_Trial_LLR_Mode`의 "그룹 수 초과" 물러서기 ([DAO_Main.py:8446](5_DAO/SRC/DAO_Main.py#L8446))와 `Initialize_Stage`의 목록이 빌 때 물러서기뿐이며, 둘 다 뒤따르는 계산이 묶음 전체로 되돌아간다
- ㉯ 구조 변경 모드 세 곳이 손보는 `target_group_indices`는 묶음 단위가 아니지만 실제로 어긋나지 않는다. 삽입 위치는 목록 안이나 목록 바로 앞으로 묶여 있고 ([DAO_Main.py:5849](5_DAO/SRC/DAO_Main.py#L5849)), 보정은 삽입 위치 이후만 밀어 올린 뒤 새 그룹을 뒤에 붙이므로 최소 index가 내려가지 않는다. 또 이 모드들은 타겟에 분기 그룹이 있으면 애초에 막힌다
- ㉰ 묶음 때문에 목록에서 빠지는 그룹은 언제나 분기 묶음의 비대표 그룹이다. 보통 그룹은 늘 홑묶음이므로 목록을 작업 대상 집합으로 쓰는 모드(REORDER_GROUP, ADJUST_ITERATION, DELETE_ROW, INSERT 위치 검사)가 그룹을 빠뜨리는 경우는 분기 묶음이 타겟에 있을 때뿐이고, 그때는 그 모드들이 모두 막힌다

### P16 HBF 최적화 모드와 SW 분기의 결합
