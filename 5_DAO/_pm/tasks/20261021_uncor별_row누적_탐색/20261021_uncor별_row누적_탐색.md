# uncor 하나씩 row를 쌓아 고치는 LLR matrix 탐색 (새 DAO 방식)

> 작성: 2026-10-21 17:58:52
> 등급: Decision (5_DAO에 새 실행 도구를 추가하고 2_LDPC_base 본체에 함수를 더한다)
> 상태: 설계 확정 (2026-10-21 사용자 답 2건과 추가 요구 1건 반영, [판정요청](%ED%8C%90%EC%A0%95%EC%9A%94%EC%B2%AD_row%EB%88%84%EC%A0%81_261021.md)). 다음은 구현 계획이다
> 측정 근거: `2_LDPC_base/_test/20261021_단일프레임_복호시간/probe.py` (11절)

이 문서에서 쓰는 말:

- ㉮ uncor: 디코더가 최대 iteration 안에 고치지 못한 프레임 (uncorrectable frame)
- ㉯ seed: 프레임 하나의 에러 패턴을 다시 만들어 내는 정수. 같은 seed와 같은 채널 설정이면 같은 프레임이 나온다
- ㉰ row: LLR matrix의 한 줄. dv(변수 노드 차수)마다 CH(채널 LLR 크기) 1개와 TH(양자화 문턱) 3개를 담고, 끝에 CSW 문턱, 적용 iteration 범위, 분기 표시가 붙는다
- ㉱ CSW(check-sum weight): 만족하지 않는 검사식의 수. 그룹 안에서 row를 고르는 기준이다
- ㉲ rank: MPI 프로세스 번호. rank 0이 root다
- ㉳ 잔여 에러 bit 수: 어떤 iteration이 끝난 시점에 codeword 전체에서 아직 틀려 있는 bit 수. 사용자가 말한 "iteration 중 최소 BER"를 이 수로 잰다
- ㉴ prefix: 지금까지 고정된 row들. stage k의 후보는 prefix 뒤에 row 하나를 붙인 매트릭스다

## 1. 목적

기존 LLR matrix로 고쳐지지 않는 uncor를 모은 뒤, uncor 하나마다 그 uncor를 고치는 작은 LLR matrix(그룹 1개, iteration 1-50)를 row 하나씩 쌓아 가며 찾는다. 모든 rank가 같은 uncor 하나를 놓고 서로 다른 후보 row를 시험하고, root가 iteration 중 잔여 에러 bit 수가 가장 작았던 후보를 골라 고정한다. 고치는 매트릭스를 찾으면 seed와 함께 저장하고 다음 uncor로 넘어간다. 새 uncor는 먼저 이미 찾은 매트릭스들로 복호해 보고, 모두 실패할 때만 새로 찾는다.

## 2. 배경

- ㉮ 지금 DAO는 매트릭스 하나를 모든 rank에 보내고 rank마다 uncor 묶음의 다른 부분을 시험해 FER로 평가한다. 평가 하나가 uncor 전체를 돌리므로 매트릭스를 크게 바꾸는 시도는 비용이 커서 작은 변이 위주로 돈다
- ㉯ 새 방식은 평가 단위를 uncor 하나와 row 하나로 줄인다. 후보 row 하나의 평가가 프레임 1개의 50 iteration 복호(측정 약 2.8초)라 rank 수만큼 후보를 넓게 시험할 수 있다
- ㉰ 디코더는 2_LDPC_base의 Python 디코더를 쓴다. 이 디코더는 iteration마다 잔여 에러 bit 수와 CSW를 돌려주므로 "iteration 중 최소 BER"를 바로 읽을 수 있다. Ref-C 실행 파일은 iteration별로 CSW만 남긴다 (8절 ㉮)
- ㉱ 지금 DAO의 GEN_SINGLE_ROW 모드가 가장 가까운 선례다. root가 1 group 1 row 후보를 만들어 모든 rank가 uncor 묶음으로 시험하고 FER와 CSW로 순위를 매긴다. 새 방식은 반대로 rank마다 다른 후보를 만들고 같은 uncor 하나로 시험한다

## 3. 요구 (사용자 설명, 2026-10-21)

- ㉮ 기존 매트릭스로 고쳐지지 않는 uncor를 먼저 모은다
- ㉯ LLR matrix는 그룹 1개(최대 iteration 50 고정), row 1개로 시작한다. rank마다 row를 따로 만들어 시험한다
- ㉰ rank마다 n번 시험한 뒤 root가 결과를 모아 iteration 중 최소 BER를 가진 row를 임시로 고정한다
- ㉱ 고정한 row를 그룹에서 CSW가 가장 큰 row 자리에 두고 모든 rank가 공유한다. 둘째 row를 붙여 둘째 row만 시험한다
- ㉲ row 1, 2가 정해지면 DAO의 변이(mutation)로 최소 BER를 더 내려도 되고, 셋째 row를 붙여도 된다. 이렇게 고쳐지는 매트릭스를 찾는다
- ㉳ 모든 rank는 같은 uncor 하나를 놓고 돈다. 고치는 매트릭스를 찾으면 다음 uncor로 넘어간다. 찾은 것은 seed와 함께 저장한다. n번 반복해도 못 찾으면 실패로 적고 넘어간다
- ㉴ 2_LDPC_base(Python)를 고쳐 이 도구에서 돌아가게 한다
- ㉵ (2026-10-21 추가) 새 uncor는 먼저 이미 찾아 둔 매트릭스들로 복호해 보고, 모두 실패할 때만 새 매트릭스를 찾는다
- ㉶ (2026-10-21 답) 반복은 두 종류다. 큰 반복은 LLR matrix 단위의 재시도이고, 작은 반복은 한 사이클 안에서 row를 찾는 반복이다. "n번"은 작은 반복이다

## 4. 설계

### 4.1 전체 흐름

```
[0 준비]       H-matrix, 기존 LLR matrix, 채널 설정을 읽는다. mpiexec로 rank N개가 뜬다
[1 uncor 모으기] seed를 0부터 세며 rank마다 나눠 기존 매트릭스로 복호한다.
               실패한 seed를 root가 모아 K개가 되면 멈추고 파일로 저장한다
               (seed 파일을 설정에 주면 이 단계를 건너뛴다)
[2 uncor 하나씩] uncor i에 대해
    먼저: 이미 찾은 매트릭스들로 uncor i를 복호 → 하나라도 고치면 그 매트릭스에 적고 다음 uncor로 (4.10)
    stage 1: rank마다 후보 row n개를 만들어 시험 → root가 최고 후보를 row 1로 고정
    (변이 블록: rank마다 row 1의 변이 후보 m개를 시험 → root가 최고를 골라 더 좋으면 교체)
    stage 2: 고정 row를 공유 → rank마다 둘째 row 후보 n개 → 최고 후보를 row 2로 고정
    (변이 블록)
    ... stage R_max까지. 어느 시험에서든 uncor가 고쳐지면 그 자리에서 끝낸다
    (큰 반복: R_max까지 실패하면 설정 횟수만큼 row 1부터 새 난수로 다시 시작)
[3 기록]       uncor마다 결과(성공/실패, 매트릭스 파일, stage별 최소 잔여 에러)를 저장한다
```

### 4.2 후보 하나의 시험

- ㉮ 입력: prefix와 후보 row 1개를 합친 그룹 1개짜리 매트릭스(iteration 1-50), uncor seed 1개
- ㉯ 실행: Python 디코더로 프레임 1개를 최대 50 iteration 복호하고 iteration마다 잔여 에러 bit 수와 CSW를 받는다
- ㉰ 출력: 성공 여부(정보 bit가 모두 맞은 iteration이 있으면 성공), 최소 잔여 에러 bit 수, 그 iteration 번호 i*, i*가 끝난 시점의 CSW
- ㉱ 순위: 성공이 먼저다. 성공이 없으면 최소 잔여 에러 bit 수가 작은 쪽, 같으면 i*의 CSW가 작은 쪽, 그래도 같으면 i*가 빠른 쪽이 앞선다
- ㉲ 같은 입력은 항상 같은 결과를 낸다 (디코더에 난수가 없고 채널은 seed로 재현된다)

### 4.3 row 쌓기 규칙

- ㉮ row 1의 CSW 문턱은 -1이다 (DAO_spec 3.5절 규칙 C1: 그룹 첫 row의 CSW는 -1). 디코더는 어떤 row의 문턱에도 들지 않는 큰 CSW에서 이 row를 쓰므로, 이 row가 사용자가 말한 "CSW가 가장 큰 row"다
- ㉯ row k(k가 2 이상)는 CSW 문턱 T_k를 갖고 T_2 ≥ T_3 ≥ ... 이다 (규칙 C5, 8의 배수, 8-1408). 디코더는 직전 iteration의 CSW가 문턱 이하인 row 가운데 가장 아래 row를 고른다. 그러므로 복호가 진행되어 CSW가 T_k 아래로 내려오면 row k가 이어받는다
- ㉰ T_k는 prefix만으로 이 uncor를 복호했을 때 최소 잔여 에러에 닿은 iteration i*가 끝난 시점의 CSW를 8의 배수로 올림한 값이다 (사용자 결정 2026-10-21, 판정요청 물음 1). 이렇게 두면 row k는 prefix가 가장 좋았던 상태 바로 다음 iteration(i*+1)부터 이어받는다. 문턱이 지켜야 할 조건은 두 가지다
  - ㉠ 앞 row보다 엄격히 작다: 8 ≤ T_k ≤ T_{k-1} - 8 (DAO 코드 `Is_LLR_Valid`가 같은 값을 오류로 본다. DAO_spec 3.5절 C5의 "내림차순"보다 엄격하다). T_2는 1408 이하면 된다
  - ㉡ 닿을 수 있다: prefix의 iteration 1-49 가운데 CSW가 T_k 이하인 iteration이 있어야 row k가 50 iteration 안에 쓰인다
  - ㉢ i*가 50이거나(마지막까지 계속 좋아지는 uncor) i*의 CSW를 올림한 값이 ㉠을 어기면, iteration 1-49 가운데 ㉠을 만족하는 CSW를 지난 iteration들 중 잔여 에러가 가장 작은 iteration의 CSW를 쓴다. 그런 iteration이 없으면 새 row가 쓰일 자리가 없으므로 이 uncor는 그 stage에서 실패로 끝낸다 (4.4 ㉰)
- ㉱ 후보 row의 값은 헤더의 min/max 범위에서 난수로 만들고 DAO 규칙(CH ≥ 0, TH ≥ 0, TH 내림차순)으로 정렬한다. 지금 DAO의 `_generate_random_row`와 같은 규칙이며 `DAO_LLR_MATRIX.Correct_Ch_Th_In_Row`를 그대로 쓴다
- ㉲ 변이(mutation)는 지금 고정한 마지막 row만 대상으로 한다. stage에서 row k를 고정한 직후 변이 블록 하나를 돈다. rank마다 row k의 변이 후보 m개를 만들어 시험하고(DAO의 MUTATE_MATRIX와 같이 CH/TH 원소 몇 개를 ±범위 안에서 바꾸고 다시 정렬한다. CSW 문턱은 그대로), root가 gather 1회로 최고를 골라 4.2 ㉱의 순위로 지금 row k보다 좋을 때만 교체한다. 블록은 stage마다 1회다 (라운드를 거듭하며 개선을 쌓는 방식이 아니다)

### 4.4 종료와 실패

- ㉮ 성공: 어느 시험에서든 uncor가 고쳐지면 그 매트릭스를 저장하고 다음 uncor로 간다. 같은 stage에서 여러 rank가 성공하면 4.2 ㉱의 순위로 하나를 고른다
- ㉯ 실패: stage R_max(기본 6)까지 성공이 없으면 실패로 적고 다음 uncor로 간다. 실패해도 stage별 최고 row와 최소 잔여 에러 이력은 남긴다
- ㉰ 조기 실패: 새 row가 이어받을 CSW 상태가 prefix의 iteration 1-49에 없으면(4.3 ㉰ ㉢) 그 stage를 돌지 않고 이 uncor를 실패로 끝낸다. history.csv에 이유 `no reachable CSW threshold`를 적는다
- ㉱ 반복은 두 종류다 (사용자 결정 2026-10-21, 판정요청 물음 2). 작은 반복은 한 사이클 안에서 row를 찾는 반복이며 stage마다 rank당 후보 수 n(`CANDIDATES_PER_RANK_PER_STAGE`)이다. 큰 반복은 매트릭스 단위의 재시도이며, R_max까지 실패하면 row 1부터 새 난수로 다시 시작하는 횟수(`MAX_MATRIX_ATTEMPTS_PER_UNCOR`, 기본 1)다. 큰 반복을 다 써도 성공이 없을 때 실패로 적는다. 조기 실패(㉰)는 큰 반복 한 번을 끝내는 것이고, 남은 큰 반복이 있으면 다시 시작한다

### 4.5 병렬 구조

- ㉮ 모든 rank가 시험한다 (root 포함). 통신은 stage마다 2회다. root가 prefix를 bcast하고, rank별 최고 후보를 root가 gather한다. 변이 블록도 같은 2회다
- ㉯ rank 안의 n개 시험은 통신 없이 돈다. 시험 하나가 약 2.8초이므로 n = 20이면 stage 하나가 약 1분이다
- ㉰ rank마다 후보 난수는 (실행 seed, rank, uncor 번호, stage, 회차)에서 파생해 재현된다
- ㉱ 집단 통신은 DAO와 같이 mpi4py를 쓴다. 대기 상한은 DAO의 TIME_CONFIG처럼 둔다

### 4.6 uncor 모으기와 seed 파일

- ㉮ 프레임 seed는 0 이상의 정수다. 채널 함수는 프레임마다 `numpy.random.default_rng(seed)`로 난수를 만든다. 같은 seed, 같은 채널 종류와 값이면 같은 프레임이다. 배치 크기와 상관없이 재현된다
- ㉯ 모으기: rank r은 seed r, r+N, r+2N, ...을 맡아 기존 매트릭스로 배치 복호하고 실패 seed를 모은다. root가 gather해 K개가 차면 멈춘다
- ㉰ 저장: `collected_uncors/uncor_seeds.txt`(한 줄에 seed 하나), `collected_uncors/info.json`(채널 종류와 값, H-matrix 파일 이름, 기존 매트릭스 파일 이름, 모은 수, 돌린 프레임 수), 기존 매트릭스 파일 사본
- ㉱ 설정에 seed 파일을 주면 모으기를 건너뛰고 그 파일을 읽는다. 같은 채널 설정이어야 하며 info.json과 대조해 다르면 멈춘다

### 4.10 찾은 매트릭스 먼저 시험

- ㉮ uncor i를 시작할 때 이미 찾은 매트릭스들(앞선 uncor를 고친 매트릭스. 실패 uncor의 매트릭스는 넣지 않는다)로 uncor i를 먼저 복호한다. 하나라도 고치면 새 탐색 없이 그 매트릭스에 uncor i를 적고 다음 uncor로 간다
- ㉯ 시험은 rank마다 나눠 돈다 (rank r이 목록의 r번째, r+N번째, ... 매트릭스). 매트릭스 하나가 후보 하나와 같은 약 2.8초라 목록이 rank 수 이하이면 한 번에 끝난다. root가 gather해 성공한 매트릭스를 고른다
- ㉰ 여럿이 고치면 지금까지 고친 uncor 수가 많은 매트릭스에 적는다 (같으면 먼저 찾은 것). 고치는 매트릭스가 몇 개로 모이게 하려는 뜻이다
- ㉱ `found_matrices.csv`에 매트릭스마다 파일 이름, 처음 고친 seed, 고친 seed 목록을 적는다. summary.csv의 결과 칸은 성공(새로 찾음), 재사용(찾은 매트릭스가 고침), 실패 셋 중 하나다
- ㉲ 설정 `TRY_FOUND_MATRICES_FIRST`가 False이면 이 단계를 건너뛴다

## 8. 범위 밖과 주의

- ㉮ Python 디코더는 Ref-C와 bit 단위로 같지 않다 (2_LDPC_base는 상대 비교 전용). 여기서 모은 uncor와 찾은 매트릭스는 Python 디코더 기준이다. Ref-C로 확인하려면 Ref-C의 seed로 같은 성격의 uncor를 다시 모아야 하며 이 작업의 범위 밖이다. 디코더 호출은 함수 하나로 모아 두어 뒤에 Ref-C 실행 파일을 끼울 수 있게 한다 (그때는 iteration별 CSW가 지표가 된다)
- ㉯ 찾은 매트릭스들을 하나의 운용 매트릭스로 합치는 일은 범위 밖이다
- ㉰ 1차는 HD 복호(fixed_error, rber 채널)만 돌린다. 구조는 모드에 묶이지 않는다
- ㉱ prefix가 공통으로 도는 구간의 디코더 상태를 저장해 두고 후보마다 거기서 이어 돌리는 속도 최적화는 1차 범위 밖이다. 후보마다 처음부터 50 iteration을 돌고 `decoder.py`는 고치지 않는다. 뒤에 속도가 문제가 되면 Review 등급 작업으로 따로 다룬다

## 9. 내가 정한 것 (사용자가 바꿔도 되는 것)

- ㉮ 지표는 codeword 전체의 잔여 에러 bit 수다 (디코더 log 항목 bit_err). 패리티 구간의 에러도 다음 iteration의 수렴에 영향을 주므로 정보 bit만 세지 않는다
- ㉯ 순위의 동점 규칙은 4.2 ㉱
- ㉰ T_k의 올림과 자르기, 닿을 수 없을 때의 대체 규칙 세부는 4.3 ㉰
- ㉱ 변이 블록은 마지막 row만 대상으로 stage마다(row 1 뒤에도) 1회 돌고, rank마다 변이 후보 m개를 시험한다. 기본 m = 10
- ㉲ 후보 row 값은 전부 난수다. 기존 매트릭스의 row를 후보로 섞는 옵션은 뒤로 미룬다
- ㉳ 모든 rank가 시험한다 (root 포함)
- ㉴ 폴더와 파일 이름은 `RowStack`, `Output_RowStack`이다. 이름은 바꿔도 된다
- ㉵ 디코더 호출은 함수 하나로 모은다 (뒤에 Ref-C를 끼울 자리)
- ㉶ seed에서 난수를 만드는 규칙은 `default_rng(seed)` 하나다. codeword는 all-zero다 (2_LDPC_base 확정 결정)
- ㉷ 새 row가 이어받을 CSW 상태가 없으면 그 uncor를 조기 실패로 끝낸다 (4.3 ㉰ ㉢, 4.4 ㉰). stage를 다시 돌리거나 문턱을 억지로 내리지 않는다
- ㉸ 디코더 상태 재개 최적화는 미룬다 (8절 ㉱)
- ㉹ 모은 uncor가 K개를 넘으면 seed가 작은 순으로 K개만 쓴다. i*가 여럿이면 가장 이른 iteration을 쓴다
- ㉺ 찾은 매트릭스 먼저 시험에서 여럿이 고치면 고친 uncor 수가 많은 쪽에 적는다 (4.10 ㉰). 실패 uncor의 매트릭스는 목록에 넣지 않는다
