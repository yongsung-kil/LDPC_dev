- ㉯ HBF2는 `row.iter_start <= HBF_MAX_ITERATION < row.iter_end`이면 오류다 ([DAO_LLR_MATRIX.py:492](../../../../../SRC/DAO_LLR_MATRIX.py#L492)). restart 그룹은 그 앞 476행의 `continue`로 HBF1, HBF2를 모두 건너뛴다
- ㉰ `Correct_Ch_Th_In_Row`는 범위 제한(814~815행) 뒤에 dv_idx 0 TH를 상수로 덮는다 (831행). 상수는 헤더 범위 제한을 거치지 않는다
- ㉱ `_generate_random_row`는 `Correct_Ch_Th_In_Row(raw_array)`로 부르며 HBF 인자를 주지 않는다 ([DAO_Main.py:793](../../../../../SRC/DAO_Main.py#L793))
- ㉲ `Gen_Trial_LLR`은 `_Protected_Groups_Changed` 다음에 `Correct_LLR_Matrix`를 부르고(2008~2022행), 유효성 검사는 `Validate_LLR_Matrix`(10075행)가 따로 맡는다
- ㉳ REGEN_DV는 재사용 모드에서 `previous_dv_segment`를 그대로 쓰고 HBF 판단은 새로 만들 때만 한다 ([DAO_Main.py:4021](../../../../../SRC/DAO_Main.py#L4021)~4037). REGEN_ROW도 `previous_gen_row`로 같은 꼴이다 (4154행)

- ㉵ `Check_Fixed_Target_Group_Idx_List`는 지금 쓰는 시퀀스 하나만 본다 ([DAO_Main.py:8360](../../../../../SRC/DAO_Main.py#L8360)). `Validate_Config`는 `RUN_OPTIMIZATION`이고 `initial_LLR_matrix`가 있을 때만 이 검사를 부른다 (10008~10011행)
- ㉶ `Set_Seed_Mode`에서 최적화 중 보통 모드 갈래는 LOAD_SEED와 LOAD_VECTOR만 받고 나머지는 `MPI_Abort`다 ([DAO_Main.py:8692](../../../../../SRC/DAO_Main.py#L8692)~8700). HBF 전용 갈래는 없다
- ㉷ `HBF_OPT_CONFIG.__init__`은 `IS_HBF_OPT`를 `init_n`에 따라 바꾸지만 부르는 자리가 없고, 실제 내리기는 `Update_RefC_Configs`가 한다 ([DAO_Config.py:369](../../../../../SRC/DAO_Config.py#L369), [DAO_Main.py:451](../../../../../SRC/DAO_Main.py#L451))
- ㉸ `GenLLRModeHBF`는 정의([DAO_Constants.py:43](../../../../../SRC/DAO_Constants.py#L43))와 `DAO_Config.py` 134행 주석에만 나온다
