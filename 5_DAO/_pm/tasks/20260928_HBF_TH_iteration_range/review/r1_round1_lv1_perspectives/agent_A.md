## 관점을 도출하며 본 코드 사실

- ㉮ `Is_Row_In_HBF_Iterations`는 `bool(self.is_HBF_OPT) and row.iter_end <= HBF_OPT_CONFIG.HBF_MAX_ITERATION`만 본다 ([DAO_LLR_MATRIX.py:106](../../../../../SRC/DAO_LLR_MATRIX.py#L106)). `__init__`이 저장하는 `self.HBF_max_iteration`([DAO_LLR_MATRIX.py:42](../../../../../SRC/DAO_LLR_MATRIX.py#L42))은 SRC 안에서 읽는 자리를 찾지 못했다
- ㉯ `Is_LLR_Valid`는 restart 그룹을 `continue`로 먼저 빼고([DAO_LLR_MATRIX.py:476](../../../../../SRC/DAO_LLR_MATRIX.py#L476)), HBF2를 row마다 DV 검사 앞에서 본다([DAO_LLR_MATRIX.py:491-497](../../../../../SRC/DAO_LLR_MATRIX.py#L491)). HBF1은 RW5 비증가 검사 뒤에 있다([DAO_LLR_MATRIX.py:520-533](../../../../../SRC/DAO_LLR_MATRIX.py#L520))
- ㉰ `HBF_immutable_col_range`는 row와 무관하게 `is_HBF_OPT`이면 `(ch_length, num_parameter_each_set)`로 한 번 정해진다([DAO_LLR_MATRIX.py:711-715](../../../../../SRC/DAO_LLR_MATRIX.py#L711)). row별 적용 여부는 `Generate_Random_Mutation`이 가른다([DAO_Main.py:7105](../../../../../SRC/DAO_Main.py#L7105))
- ㉱ `Correct_Ch_Th_In_Row`는 truncation 뒤 HBF 구간 row의 dv_idx 0 TH를 상수로 덮고, 이 덮어쓰기는 `correct_msg`에 남지 않는다([DAO_LLR_MATRIX.py:812-833](../../../../../SRC/DAO_LLR_MATRIX.py#L812))
- ㉲ trial 경로는 `_Protected_Groups_Changed`(2009) 다음 `Correct_LLR_Matrix`(2022) 다음 `Update_Current_LLR`이고, 유효성 검사는 `Is_Current_LLR_Valid`에서 `Validate_LLR_Matrix`로 따로 돈다([DAO_Main.py:2007-2031](../../../../../SRC/DAO_Main.py#L2007), [DAO_Main.py:2507-2508](../../../../../SRC/DAO_Main.py#L2507)). 초기 매트릭스는 보정 없이 `Validate_LLR_Matrix`로 가고 실패하면 중단한다([DAO_Main.py:2361-2362](../../../../../SRC/DAO_Main.py#L2361))
- ㉳ `_generate_random_row`는 `Correct_Ch_Th_In_Row(raw_array)`를 인자 없이 불러 dv_idx 0 TH를 난수로 둔다([DAO_Main.py:795](../../../../../SRC/DAO_Main.py#L795)). 호출자는 2074, 2414, 2690, 10372행이다
- ㉴ `Gen_LLR_Regen_DV`(4030)와 `Gen_LLR_Regen_Row`(4167)는 새 값을 만들 때만 HBF 판단을 하고, 재사용 모드에서는 `previous_dv_segment`, `previous_gen_row`를 그대로 쓴다([DAO_Main.py:4021-4022](../../../../../SRC/DAO_Main.py#L4021), [DAO_Main.py:4154-4155](../../../../../SRC/DAO_Main.py#L4154))
- ㉵ 미세 조정과 거친 조정 변이는 이전 변이의 `(group, row, col)`을 그대로 다시 쓴다([DAO_Main.py:3826-3915](../../../../../SRC/DAO_Main.py#L3826))
- ㉶ `Gen_LLR_Insert_Random_Group`의 새 그룹은 `ref_iter_end + 1`부터 `INSERT_GROUP_NUM_ITERATION`(20)칸이고, 삽입 위치 뒤 모든 그룹의 iteration을 민다([DAO_Main.py:2644-2720](../../../../../SRC/DAO_Main.py#L2644), [DAO_Config.py:258](../../../../../SRC/DAO_Config.py#L258))
- ㉷ `Gen_LLR_Split_Group`의 back 그룹 변이는 `_generate_mutation_for_group`이 모든 column을 후보로 삼는다([DAO_Main.py:3430-3444](../../../../../SRC/DAO_Main.py#L3430), [DAO_Main.py:3516-3519](../../../../../SRC/DAO_Main.py#L3516))
