용어 (이 문서 안에서 쓰는 뜻)
- ㉮ VN, CN: 변수 노드(variable node, H의 열 하나 = 부호 비트 하나), 검사 노드(check node, H의 행 하나 = 패리티 검사식 하나)
- ㉯ trapping set(TS): 디코더가 갇히는 VN 집합. (a,b)는 그 VN a개와, 그 집합이 만드는 불만족 CN b개
- ㉰ 유도 부분 그래프 G(S): VN 집합 S와 그 이웃 CN, 그 사이 간선만 남긴 그래프. CN의 차수가 홀수면 불만족, 짝수면 만족(mis-satisfied, 오류가 짝수 개 걸려 만족으로 보이는 CN)
- ㉱ elementary TS(ETS): G(S)의 CN 차수가 1 또는 2뿐인 TS. leafless ETS(LETS): ETS 중 차수 2 CN만으로 이은 VN 그래프(normal graph)에서 모든 VN의 차수가 2 이상인 것
- ㉲ absorbing set: S의 모든 VN이 불만족 CN보다 만족 CN에 더 많이 연결된 TS (bit flipping 류 디코더의 고정점)
- ㉳ girth g: Tanner 그래프의 최단 사이클 길이. ACE(approximate cycle extrinsic message degree): 사이클 위 VN들의 (차수 - 2) 합. 작을수록 사이클이 바깥과 덜 이어져 유해
- ㉴ QC(quasi-cyclic): H가 z×z 순환 치환 블록으로 이루어진 구조. 본 저장소의 `QCCode`(base matrix와 z). 블록 j의 lane l이 VN 하나다
- ㉵ 궤도(orbit): QC 대칭(모든 lane을 같이 1 이동)으로 서로 옮겨지는 구조들의 모임. 한 궤도의 크기는 보통 z

## 1. 목적, 범위, 비목표

### 목적
- ㉮ 실패 진단: 디코딩에 실패한 프레임 하나에서 "어느 VN 집합이 어떤 (a,b) 구조로 갇혔고, 그 안의 사이클은 무엇이며, 안정형인지 진동형인지"를 보고서로 낸다. 여러 실패를 모아 (a,b) 빈도표를 만든다
- ㉯ H 조사: 주어진 H의 girth, 길이별 사이클 수, 열 블록별 사이클 수, 짧은 사이클 목록과 ACE 분포, (a,b) 상한 안의 trapping set 목록을 낸다
- ㉰ 두 결과를 잇는다: 실패 진단이 찾은 VN 집합을 H 조사의 trapping set 목록과 대조해 "알려진 구조에 갇혔는지, 새 구조인지"를 말한다

### 범위 안
- ㉮ 입력 H는 `QCCode`가 읽는 Ref-C 포맷 QC-LDPC. 열 가중치가 섞인 부호(2, 3, 4 등)와 girth 4(길이 4 사이클이 있는 H)도 받는다
- ㉯ 디코더는 `2_LDPC_base/src/decoder.py`의 `BaseDecoder`와 그 자식(상속 변형). 모드 HD, 2SD, 3SD
- ㉰ 송신 codeword는 all-zero (시뮬레이터 확정 결정). 따라서 "오류 VN = 판정 비트가 1인 VN"이다

### 비목표 (이번 작업에서 하지 않는 것)
- ㉮ 디코더 성능 개선(후처리 디코더 구현). Kang의 backtracking은 "진단 검증" 용도로만 쓴다
- ㉯ 비기본(non-elementary) trapping set의 완전 탐색. 진단에서 발견되면 보고만 한다
- ㉰ error floor 수치 추정(importance sampling). 빈도표까지만 낸다
- ㉱ C++ Reference-C 쪽 연동

### 실패로 간주하는 것 (anti-goal)
- ㉮ 진단 모듈을 켠 것만으로 2_LDPC_base 실험 결과가 달라지는 것 (src 수정 금지, 기록은 상속으로)
- ㉯ 사이클 수가 교차 검증과 어긋나는 것 (소형 H에서 완전 열거, Hashimoto 행렬 대각합과 반드시 일치)
- ㉰ 결과 문서나 로그에 입력 파일의 출처나 성격을 적는 것 (파일은 이름과 치수로만)

|------|------|-----------------|
| 부호 표현 | `QCCode(base, z)`: `edge_row`, `edge_col`, `edge_shift`(base 간선 E_base개), `col_deg`, `row_deg`, `syndrome(bits)` | Tanner 그래프를 base 간선과 z로부터 전개한다. 예시 H(base 18×147, z=256)는 간선 141,568개, N=37,632 |

## 4. 모듈 설계

### 4.1 tanner_graph.py (공통 자료 구조)

- ㉮ 전개: VN 평면 번호 v = j*z + l (블록 j, lane l), CN 평면 번호 c = i*z + k. base 간선 (i, j, s)는 lane l의 VN을 CN lane (l + s) mod z 에 잇는다 (pcm.py 모듈 설명의 연결 규칙 `cn = np.roll(v, -s)` 와 같은 방향). 구현 뒤 `QCCode.syndrome()`과 같은 결과가 나오는지 검사한다
- ㉯ 저장: CSR 두 벌. `vn_ptr, vn_adj`(VN별 이웃 CN), `cn_ptr, cn_adj`(CN별 이웃 VN), 그리고 간선 번호 `vn_edge`, `cn_edge`(같은 간선을 양쪽에서 가리킴). 모두 int32 numpy. 메모리는 간선 수의 상수 배
- ㉰ QC 이동: `shift(vn_set, t)` = 모든 VN의 lane에 t를 더함(mod z). `orbit_representative(vn_set)` = z개 이동 중 정렬 튜플이 가장 작은 것. `orbit_size(vn_set)` = 서로 다른 이동의 수(보통 z, z의 약수일 수 있음)
- ㉱ 유도 부분 그래프 분석 `analyze_vn_set(S)`: 이웃 CN별 차수, 불만족 CN(홀수), mis-satisfied CN(짝수 2 이상), (a,b), elementary 여부, leafless 여부, absorbing 여부(Zhang 2009 조건: S의 모든 VN에서 불만족 이웃 수 < 만족 이웃 수), normal graph 간선 수, 연결 성분 분해
- ㉲ 좌표 표기: 모든 출력에서 VN은 `(블록, lane)`, CN은 `(블록행, lane)`으로 적는다 (평면 번호는 내부용)

### 4.2 cycle_census.py (사이클 세기와 열거)

사이클 수 (Karimi 2013 메시지 전달, 노트 A 절 1)
- ㉮ 시작 노드: 열 블록마다 lane 0의 VN 하나씩 (N_b개). QC 대칭으로 같은 블록의 VN은 사이클 수가 같으므로 블록별 결과 = 그 블록 모든 VN의 결과
- ㉯ 메시지: 간선마다 길이 d_u(시작 VN의 차수)인 int64 벡터. 배열 모양 (E, d_u) 두 벌(VN에서 CN으로, CN에서 VN으로). 갱신은 "노드별 합(np.add.reduceat 또는 bincount) 뒤 자기 입력 빼기"
- ㉰ 반복 k = 1..g-1. 반복 k에 시작 VN으로 돌아온 메시지에서 자기 변수 지수를 뺀 합을 2로 나눈 것이 N^{u}_{2k} (식 2). 전체 수는 N_{2k} = z * (블록별 N^{u}_{2k} 합) / k (Li, Lin 식 5. 대표 노드만 쓰므로 노드 제거 방식 대신 k로 나눈다)
- ㉱ 정확 범위: 길이 2g-2까지. girth 6이면 6, 8, 10. girth 4면 4, 6. 그 밖의 길이는 표에 "미지원(정확 범위 밖)"으로 적고 값을 내지 않는다
- ㉲ girth: 첫 반복에서 0이 아닌 메시지를 받는 k로 판정 (g = 2k). `count_cycles4()`가 0이 아니면 g = 4로 바로 확정
- ㉳ 복잡도: 시작 노드당 O(g * E * d_u). 예시 H는 147 × 5 × 141,568 × 4 ≈ 4.2e8 정수 연산이며 numpy 벡터 연산이라 수십 초 안을 목표로 한다

교차 검증 함수 (소형 H 전용, 테스트에서 사용)
- ㉮ Hashimoto 방향 간선 행렬 A_e(2E × 2E)의 대각합: N_k = tr(A_e^k) / (2k), k < 2g (Karimi 식 4). numpy 밀집 행렬로 E가 수백 이하일 때만
- ㉯ 완전 열거: 소형 H에서 DFS로 단순 사이클을 전부 세는 느린 참조 구현
- ㉰ Dehghan 정리 1: BFS 경로 수로 N_g 계산. 세 결과가 모두 같아야 한다

짧은 사이클 열거 (trapping set 탐색의 입력, Hashemi Routine 5, 노트 B 절 4)
- ㉮ `enumerate_chordless_cycles(k)`: 길이 2k 사이클 중 chord가 없는 것(s_k)을 VN 튜플과 CN 튜플로 반환. 시작 VN은 lane 0 대표만 쓰고, 각 사이클은 궤도 대표로 정규화해 중복을 없앤다. 모든 궤도가 lane 0 VN을 포함하는 원소를 가지므로 빠지는 궤도는 없다
- ㉯ 범위: k = g/2 .. K. K는 trapping set 탐색이 요구하는 값(기본 g/2 + 1, 즉 girth 6이면 s_3과 s_4). 열거 수가 상한(기본 2,000,000 궤도)을 넘으면 중단하고 보고한다
- ㉰ ACE: 사이클마다 sum(d_v - 2). VN별 "자기를 지나는 최소 ACE"와 지역 girth를 함께 낸다 (Abdu-Aguye 2016의 출력 형식, 알고리즘은 열거 결과 집계로 대체)

출력
- ㉮ `cycle_counts.csv`: 길이, 전체 수, 정확 여부
- ㉯ `cycle_counts_by_block.csv`: 열 블록, 열 가중치, 길이별 수
- ㉰ `short_cycles.jsonl`: 궤도 대표 사이클마다 {길이, vns: [(블록, lane)...], cns: [...], ace, orbit_size}
- ㉱ `ace_by_block.csv`: 열 블록별 최소 ACE, 지역 girth

### 4.3 trapping_set_search.py (trapping set 열거)

방식 (사용자 결정 대기, 판정요청 물음 1. 아래는 권고안 기준)
- ㉮ 시작 구조: 4.2의 chordless 사이클 s_k (k = g/2..K)와, leaf 있는 ETS용으로 차수 b_max 이하의 단일 VN (Hashemi 2017)
- ㉯ 확장 세 가지를 Tanner 그래프 위에서 구현 (노트 B 절 2, 4)
  - ㉠ dot: V\S 중 불만족 CN 2개 이상에 연결되고 만족 CN에는 연결이 없는 VN을 하나 붙임 (Routine 6)
  - ㉡ path: 서로 다른 불만족 CN 두 개에서 나가는 경로가 같은 노드에서 만나고 G(S)와 겹치지 않을 때 그 경로의 VN들을 붙임 (Routine 7)
  - ㉢ lollipop: 불만족 CN에서 나간 경로가 G(S)와 겹치지 않는 다른 사이클 S'의 불만족 CN에서 끝날 때 경로 VN과 S'를 붙임 (Routine 8). S'는 4.2의 사이클 목록을 재사용
  - ㉣ leaf: 불만족 CN 하나에만 연결되고 만족 CN에 연결 없는 VN을 붙임 (Hashemi 2017 Algorithm 1의 dot_k^1)
- ㉰ 가지치기: 논문의 특성화 표 대신 "크기별 b 상한" 재귀를 쓴다 (Hashemi 2017 Theorem 2): b_max^{a} = min{ b_max^{a+1} + max{y, 2a - z}, a(η - 2) }, 초기 b_max^{a_max} = b_max. 확장 결과의 (a', b')가 상한 밖이면 버린다. 확장 종류별 (a,b) 변화식은 노트 B 절 7 Proposition 3
- ㉱ 중복 제거: 인스턴스를 궤도 대표(정렬 튜플)로 정규화해 집합에 넣는다. 같은 궤도는 한 번만 탐색하고 `orbit_size`를 기록한다
- ㉲ 분류: 결과마다 (a,b), elementary, leafless, absorbing, fully absorbing(선택, 비용 큼), 부모 사이클 길이, 적용한 확장 열
- ㉳ 범위 기본값: a_max 6, b_max 2 로 시작해 시간을 재고 올린다. 인자로 받는다. 시간 상한(기본 30분)을 넘으면 그때까지 결과를 저장하고 중단 사실을 보고서에 적는다
- ㉴ 완전성에 대한 입장: 논문의 완전성 증명은 특성화 표(nauty geng으로 생성)에 기대므로, 이 구현은 "확장 규칙 세 가지와 leaf 확장을 b 상한 안에서 모두 적용한 탐색"이다. 완전성은 ㉮ 소형 H에서 완전 탐색(모든 VN 부분집합 검사)과 비교, ㉯ 실패 진단이 찾은 VN 집합이 범위 안인데 목록에 없는 사례가 있는지 감시, 두 가지로 확인한다

출력
- ㉮ `trapping_sets.jsonl`: {a, b, vns: [(블록, lane)...], unsat_cns, kind: "LETS" | "ETSL" | "ETS", absorbing: true/false, normal_edges, parent_cycle_len, expansions: [...], orbit_size}
- ㉯ `trapping_set_classes.csv`: (a,b)별 궤도 수, 인스턴스 수(궤도 수 × 궤도 크기), absorbing 수
- ㉰ `report.md`에 (a,b) 표와 가장 작은 구조들의 그림(텍스트 인접표)

### 4.4 failure_diagnosis.py (실패 진단)

기록용 디코더
- ㉮ `class RecordingDecoder(BaseDecoder)`: `_record_iteration(self, state, collect_profile)`를 같은 인자로 재정의. `super()`를 부른 뒤 `state.decision_bits.copy()`와 `state.idx_active.copy()`를 반복 번호와 함께 리스트에 보관. 재정의는 이 함수 하나뿐이라 교체 지점 6개와 충돌하지 않는다
- ㉯ 사용 방식: 실패 프레임 하나씩(B=1) 재복호한다. 메모리는 반복 120 × 37,632 비트 = 약 4.5 MB (uint8 기준)
- ㉰ 변형 디코더(3_LDPC_ideas 자식 클래스)를 진단하려면 그 클래스를 인자로 받아 같은 재정의를 동적으로 입힌다 (`type("Recording"+이름, (클래스,), {...})`). 설계 단계에서는 BaseDecoder만 보장한다

실패 샘플 공급
- ㉮ 입력 A: RowStack 형식 폴더 (`uncor_seeds.txt`, `info.json`). info.json의 channel_type, channel_point, mode, strong 비율을 그대로 쓴다
- ㉯ 입력 B: `--seed-range 시작 끝` 과 채널 인자. 도구가 `decode_frame_seeds`로 실패 seed를 추려 같은 형식으로 `collected_uncors/`에 저장한 뒤 진단한다 (수집기 역할)
- ㉰ 두 경우 모두 프레임 생성은 `channel_output_from_frame_seeds`로 하고, 실패 여부는 본 디코더(기록 없음)로 먼저 확인한 뒤 기록용 디코더로 재복호한다. 두 결과가 다르면(비결정성) 오류로 중단한다
- ㉱ 재복호하면 성공하는 seed(다른 LLR matrix나 디코더로 진단할 때 생긴다)는 진단에서 빼고 "재복호 성공 n건"으로 보고서와 `failures.csv` 요약에 적는다. 오류가 아니다. 통계의 분모는 실제로 실패한 건수다
- ㉲ 입력 우선순위: H와 LLR matrix는 CLI 인자 `--h`, `--llr`가 정한다 (필수). `info.json`의 `h_matrix_file`, `initial_llr_matrix_file`은 파일 이름만 대조해 다르면 보고서 머리에 "수집 때와 다른 파일로 진단함"이라고 적는다. 채널 종류, point, strong 비율, mode는 `info.json` 값을 쓰되 같은 이름의 CLI 인자가 있으면 CLI가 이긴다

프레임 1건 진단 절차 (노트 C의 정의를 아래 순서로 조합)
- 1. 궤적 정리: 반복 r마다 오류 VN 집합 T_r = {v : decision_bits[r][v] = 1}, 불만족 CN 집합 C_r = {c : (H T_r)_c = 1}. r = 0은 채널 출력 그대로(read_bit)이고 보고용으로만 싣는다. |C_r| 수열과 |T_r| 수열을 보고서에 싣는다
- 2. 갇힌 반복 rho_min = r ≥ 1 중 |C_r|이 최소인 가장 이른 반복 (Han 2022 Definition 1, 동률은 가장 작은 r). T = T_{rho_min}, C_U = C_{rho_min}, (a,b) = (|T|, |C_U|). 마지막 반복의 (a,b)도 함께 적는다
- 3. 유도 부분 그래프: `analyze_vn_set(T)`로 CN 차수, mis-satisfied CN, elementary, leafless, absorbing 여부, 연결 성분. 성분이 여럿이면 성분마다 (a,b)를 따로 낸다 (Han 2022 가정 7)
- 4. 사이클: G(T) 안에서 길이 g, g+2, g+4 (4.2의 표기로 k = g/2..g/2+2) 사이클을 열거해 "이 trapping set을 이루는 사이클" 목록을 낸다 (4.2의 열거를 부분 그래프에 적용). 사이클마다 ACE
- 5. 안정형과 진동형: 마지막 16 반복(또는 전체 반복이 더 짧으면 그 절반)의 T_r가 모두 같으면 안정형(Zhang 2009), 아니면 T_r 해시 수열의 최소 주기를 구해 주기 p의 진동형, 주기가 없으면 불안정형(Han-Ryan 2009의 unstable)
- 6. error path (Han 2022 Definition 3, 4): C_U의 CN 쌍마다 G(T) 안에서 오류 VN과 mis-satisfied CN만 지나는 경로를 BFS로 열거 (길이 상한 l_max = ((d_c - 1)(d_v - 1))^(l_max - 1) > n 인 최소 정수). VN을 shallow(불만족 CN에 인접)와 deep으로 나눈다. b = 1이면 그 CN의 이웃 VN 하나씩
- 7. 대조: T의 궤도 대표를 trapping set 목록과 비교한다. ㉮ 같은 VN 집합이 있으면 "목록의 구조 n번", ㉯ 없고 (a,b)와 normal graph 간선 수, 차수열이 같은 것이 있으면 "같은 클래스(모양 추정)", ㉰ 범위 안인데 없으면 "목록 누락 후보"로 표시(완전성 감시), ㉱ 범위 밖이면 "범위 밖"
- 8. (선택, `--backtracking`) Kang 2011 검증: N(C_U)의 VN v마다 채널 출력의 그 비트를 u0[v]의 반대로 바꿔(HD는 read bit 반전, SD는 반대 극성의 가장 강한 region) 재복호한다. 성공하는 v가 경계 노드다. 재복호 횟수가 |N(C_U)| ≈ b × d_c 이므로 기본은 끈다

여러 건 통계
- ㉮ `failures.csv`: seed, rho_min, 마지막 반복, (a,b) at rho_min, (a,b) at last, 유형(안정/진동/불안정), elementary, absorbing, 성분 수, 대조 결과, 최소 ACE
- ㉯ `class_histogram.csv`: (a,b)와 유형별 건수, 궤도 대표별 건수(같은 구조가 반복되는지)
- ㉰ `diagnosis_report.md`: 요약표와 상위 구조 5개의 상세

## 5. 알고리즘 요점 (구현자가 노트를 읽기 전에 알아야 할 것)

- ㉮ 사이클 세기 정확 범위는 2g-2까지다 (Karimi Lemma 2). 더 긴 길이는 두 사이클이 합쳐진 보행이 섞여 값이 커진다. 이 도구는 그 값을 내지 않는다
- ㉯ 메시지에서 "자기 변수 제외"를 빼먹으면 꼬리 달린 보행이 사이클로 세인다 (Karimi 식 2)
- ㉰ 대표 노드만 시작하면 노드 제거 최적화를 못 쓰므로 반드시 k로 나눈다 (Li, Lin 식 5)
- ㉱ chordless 사이클 열거의 조건은 "두 경로가 끝 노드만 공유하고, 끝 VN을 뺀 두 경로의 VN들이 공통 CN을 갖지 않음"이다 (Routine 5)
- ㉲ irregular 확장의 (a,b) 변화: dot은 (a+1, b + k - 2m) (k = 새 VN 차수, m = 붙인 불만족 CN 수), path와 lollipop은 (a+m, b - 2 + sum(dv_i - 2)) (Hashemi 2017 Proposition 3)
- ㉳ absorbing 판정은 "S의 모든 VN에서 불만족 이웃 수 < 만족 이웃 수"이고 등호는 포함하지 않는다 (Zhang 2009)
- ㉴ 갇힌 반복은 마지막 반복이 아니라 불만족 CN 수가 최소인 가장 이른 반복이다 (Kang, Han 2022). 마지막 반복의 집합은 진동 중일 수 있다
- ㉵ 디코더 내부 CSW(check_sum ⊕ syndrome의 합)는 V2C 부호 기준이라 판정 비트의 신드롬 가중치와 다를 수 있다. 진단은 판정 비트의 신드롬으로 센다

순서를 이렇게 둔 이유: 사이클 열거는 둘 다에 필요하고, 실패 진단이 사용자의 첫 질문에 직접 답하며 구현 위험이 가장 작다. trapping set 탐색은 폭증 위험이 있어 마지막에 둔다.

## 9. 설계자가 정한 것 (되돌리기 쉬운 선택. 다르게 원하시면 말씀해 주세요)

- ㉮ 사이클 세기 알고리즘: Karimi 2013 메시지 전달을 기본으로 하고 QC 대표 노드로 z배 절감. Smarandache 그룹의 QC 전용 다항식 방식은 열 가중치 3 완전 연결 형태 중심이라 irregular H에 바로 맞지 않아 뺐다
- ㉯ 의존성: numpy만. scipy, networkx, numba 추가 없음 (시뮬레이터 방침과 같음)
- ㉰ 실패 샘플 공급: RowStack의 uncor seed 파일 형식을 그대로 입력으로 받고, 수집기도 같은 형식으로 쓴다. 2_LDPC_base 실험 run과 src는 건드리지 않는다
- ㉱ 디코더 상태 기록: `_record_iteration` 재정의 자식 클래스. src에 로그 항목을 추가하지 않는다
- ㉲ 탐색 범위 기본값: a_max 6, b_max 2. 시간 상한 30분. 모두 인자
- ㉳ 출력 위치: `4_H_matrix_tool/out/` (git 무시). 남길 요약은 사람이 문서로 옮긴다
- ㉴ 테스트 위치: `4_H_matrix_tool/tests/` (커밋 대상)
- ㉵ Kang backtracking 검증은 선택 옵션, 기본 꺼짐
- ㉶ 합성 실패 시험은 둘로 나눈다. 가짜 궤적을 직접 넣는 단위 시험(T8a)이 정확 일치를 요구하고, 디코더를 거치는 통합 시험(T8b)은 자기 일관성만 요구한다 (디코더가 입력 구조를 고칠 수도 있고 일부만 고칠 수도 있어서)
- ㉷ 진단 입력의 우선순위: H와 LLR matrix는 CLI 인자가 정하고 `info.json`은 대조와 경고에만 쓴다. 재복호하면 성공하는 seed는 오류가 아니라 "재복호 성공 n건"으로 센다 (RowStack이 모은 실패를 다른 LLR matrix로 진단하는 쓰임을 위해)
- ㉸ 갇힌 반복 rho_min은 반복 1 이상에서 고른다. 반복 0(채널 출력 그대로)은 보고용으로만 싣는다 (Kang, Han 2022의 정의 범위와 같게)
