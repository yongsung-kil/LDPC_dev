## 물음 1. trapping set 목록을 뽑을 때 어느 방식으로 만들까?

- 🔎 예시: 예시 H(base 18×147, z=256)에서 a가 6 이하, b가 2 이하인 trapping set 목록을 뽑고, 실패 프레임 50건을 진단해 목록과 대조하는 장면
  - 10:00:00 `analyze_h_matrix.py`가 짧은 사이클을 열거하고 확장해 목록을 만든다
  - 10:20:00 `diagnose_failures.py`가 실패 50건에서 갇힌 VN 집합을 뽑아 목록과 대조한다
  - 1️⃣ 이면: 목록 생성에 외부 프로그램이 필요 없다. 50건 중 47건은 "목록의 구조 n번"으로 나오고, 3건은 (6,2)인데 목록에 없어 "목록 누락 후보"로 표시된다. 이 3건이 바로 탐색이 놓친 구조이므로 그 모양을 보고 확장 규칙을 보강할 수 있다
  - 2️⃣ 이면: 먼저 nauty(그래프 동형 판정 도구 모음)의 geng 실행 파일을 Windows에 설치하고, 논문의 표 생성 알고리즘을 추가로 구현한다. 그 뒤 결과는 1️⃣와 같은 목록이되 "논문이 증명한 완전 탐색"이라는 보증이 붙는다. 열 가중치가 섞인 우리 H는 2017년 후속 논문의 추가 절차까지 넣어야 보증이 성립한다
  - 3️⃣ 이면: 가장 빨리 목록이 나오지만 dot 확장만 쓰므로 path나 lollipop으로만 생기는 구조를 처음부터 못 찾는다. 50건 중 10건이 "목록에 없음"으로 나오는데, 그것이 탐색의 누락인지 범위 밖인지 구분할 수 없다
- 📌 상황: trapping set(TS)은 디코더가 갇히는 변수 노드 집합이고 (a,b)는 그 집합의 변수 노드 수 a와 불만족 검사 노드 수 b다. 목록은 짧은 사이클에서 출발해 "확장 규칙"으로 노드를 붙여 가며 만든다. 확장 규칙은 세 가지다 (dot: 노드 하나를 불만족 검사 노드 둘 이상에 붙임, path: 불만족 검사 노드 두 개 사이를 새 경로로 이음, lollipop: 불만족 검사 노드에서 나간 경로 끝에 다른 사이클을 붙임). 기반 논문(Hashemi 2016)은 "어느 (a,b) 클래스에 어느 확장을 적용해야 빠짐없이 나오는가"를 적은 특성화 표를 먼저 만들고 그 표대로만 확장한다. 이 표를 만들려면 모든 비동형 그래프를 생성하는 외부 도구 nauty geng이 필요하다. 지금 저장소에는 trapping set 탐색 코드가 없다
- ⚠️ 문제: 표 없이 세 확장을 모두 적용하면 결과는 같을 가능성이 높지만 "빠짐없다"는 증명은 없다. 표를 만들면 증명은 생기지만 외부 도구 설치와 구현량이 늘고, 우리 H처럼 열 가중치가 섞인 부호는 후속 논문의 절차까지 더해야 한다
- ❓ 결정할 것
  - 1️⃣ (권고) 세 확장과 leaf 확장을 모두 적용하고 크기별 b 상한으로 가지치기한다. 외부 도구 없음. 완전성은 소형 H 완전 탐색 비교와 실패 진단의 "누락 후보" 표시로 감시한다. 고칠 범위: trapping_set_search.py 하나. 되돌리기 쉬움 (나중에 2️⃣를 덧붙일 수 있음)
  - 2️⃣ nauty geng을 설치하고 Hashemi 2016의 표 생성 알고리즘과 2017 irregular 절차를 구현해 논문대로 한다. 고칠 범위: trapping_set_search.py와 표 생성 모듈, 설치 안내. 구현량 약 두 배. 되돌리기는 쉬우나 투자한 시간은 못 돌림
  - 3️⃣ Karimi 2012처럼 dot 확장만 쓴다. 가장 단순. 구조를 놓친다는 것이 논문에 기록되어 있음. 되돌리기 쉬움
  - 권고 까닭: 이 도구의 목적은 "실패를 설명하는 것"이지 논문 수준의 완전성 증명이 아니다. 1️⃣는 진단 결과가 스스로 누락을 드러내므로 실용적으로 충분하고, 외부 도구 없이 numpy만으로 끝난다
  - 권고가 맞지 않는 경우: 이 목록을 외부(논문, 보고서)에 "완전 탐색 결과"로 제시해야 한다면 2️⃣가 맞다
